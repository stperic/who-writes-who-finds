Known vulnerability:
CVE-2026-33321 (server-side request forgery, OWASP A10), file interface/forms/eye_mag/report.php.
This change adds the eye exam report, which echoes stored, user-supplied values without
escaping into HTML and into CSS url() contexts (for example background: <?php echo $background; ?>
and free-text fields such as HPI, motility, visual field, Rx type and plan/order details). The
patient report page renders forms' report.php output server-side into a PDF with an HTML-to-PDF
renderer, which fetches URLs in the markup. Injected URLs are therefore fetched by the server:
out-of-band server-side request forgery. The root cause is the missing output escaping; the
same flaw also allows HTML injection in the browser view.

# Security Review: `interface/forms/eye_mag/report.php`

**Context:** `custom_report.php` loads this file with `include_once` for every patient that has an `eye_mag` form. The top-level code therefore runs in the global scope of the patient report. It can overwrite that report's variables, such as `$pid` and `$encounter`.

---

## 1. Request parameters overwrite the session patient/encounter (IDOR)

**Location:** `report.php`, top-level code:
```php
if ($_REQUEST['ptid']) $pid = $_REQUEST['ptid'];
if ($_REQUEST['encid']) $encounter=$_REQUEST['encid'];
if ($_REQUEST['formid']) $form_id = $_REQUEST['formid'];
if ($_REQUEST['formname']) $form_name=$_REQUEST['formname'];
```

**Category:** A01 Broken Access Control

**Severity:** High

**Problem:**
- `$pid` is normally the patient bound to the user's session, set in `globals.php`.
- Because this file is included into `custom_report.php`, any request with `?ptid=N` replaces that global `$pid`.
- Everything that runs afterwards then uses the attacker-chosen patient. That includes demographics, history, insurance, billing, immunizations, notes, transactions and the forms themselves.
- No ACL check confirms the user may access that patient. This allows unauthorized disclosure of any patient's PHI.
- The same applies to `encid` and `formid`.

**Fix:**
- Remove these overrides entirely.
- If a standalone entry point is needed, put it in a separate file. That file should check the ACL (`acl_check('patients','med')` / encounters) and validate that the encounter and form belong to the session patient.

## 2. SQL injection via the overwritten `$pid` (pre-existing code relied on)

**Location:** `custom_report.php`. These queries run after `report.php` is included:
```php
" where i1.patient_id = '$pid' and i1.added_erroneously = 0 "
"... WHERE batchcom.patient_id='$pid'"
```

**Category:** A03 Injection

**Severity:** Critical

**Problem:**
- `$pid` is normally a trusted integer. Issue 1 makes it fully attacker-controlled through `$_REQUEST['ptid']`, and it is concatenated directly into SQL.
- Setting `$sanitize_all_escapes=true` in `report.php` does nothing, because `globals.php` was already loaded by the includer.
- An input like `ptid=1' UNION SELECT ...` gives arbitrary database reads, including users and password hashes.
- The same file has other pre-existing concatenations: `forms where pid = '$pid'`, `lists WHERE id = '$rowid'` and `form_id IN (...)` built from keys.

**Fix:**
- Remove issue 1.
- Convert these queries to bound parameters (`sqlStatement($sql, array($pid))`).

## 3. SQL injection in `display_draw_image()`

**Location:**
```php
$base_name = $pid."_".$encounter."_".$side."_".$zone."_VIEW";
$sql = "SELECT * from documents where documents.url like '%".$filename."'";
```

**Category:** A03 Injection

**Severity:** Critical

**Problem:**
- `$encounter` comes from `custom_report.php` as `$form_encounter = $val`, where `$val` is the raw GET/POST value of `eye_mag_<id>`. It can also come from `$_REQUEST['encid']`, and `$pid` from issue 1.
- These values are concatenated straight into a `LIKE` clause.
- Example: `eye_mag_5=1' UNION SELECT ... -- ` injects SQL.

**Additional problem:** The lookup does not restrict documents to the current patient (`foreign_id`). A crafted pattern can therefore return and render another patient's document.

**Fix:**
- Use `sqlQuery("SELECT * FROM documents WHERE url LIKE ? AND foreign_id = ?", array('%'.$filename, $pid))`.
- Cast `$pid` and `$encounter` to int.

## 4. SQL injection via session facility

**Location:** `narrative()`:
```php
$sql = "select * from facility where id=" . $_SESSION['pc_facility'];
```
The same pattern appears in `custom_report.php`.

**Category:** A03 Injection

**Severity:** Low

**Problem:** A session value is concatenated into SQL. It is not directly user-supplied, but this is still unsafe.

**Fix:** Bind it as a parameter.

## 5. Stored XSS: clinical data echoed without encoding

**Location:** Multiple places in `narrative()` and `display_draw_image()`:
- `<?php echo $HPI1; ?>`
- `echo "&nbsp;".$CHRONIC2` and `$CHRONIC3`
- `echo ($CTLOSVA?:"-")`
- The motility cells `echo $MOTILITY_RRSO` and the others. These are only prefixed with "-", not encoded.
- Impression/Plan: `echo $item['codetext']`, `echo $item['code']` and `echo $item['plan']`. The plan has newlines converted to `<br>`, but its HTML is not escaped.
- `foreach ($PLAN_items ...) echo $item`, and `echo $PLAN2`.
- `echo '<td>'.$note->get_note()...` for document notes.
- `$providerNAME` in the PDF signature block.
- `$filetoshow` / `$from_file` placed into `src='...'` without `attr()`.

**Category:** A03 Injection (XSS)

**Severity:** High

**Problem:**
- Any user who can edit an eye exam, a plan, or a document note can store script.
- That script runs in the browser of every clinician who views the patient report or encounter summary.
- The result is session hijacking or actions taken as that clinician, possibly an admin.
- In PDF mode, injected HTML can also add `<img src>` references to local files, which html2pdf will then fetch.

**Fix:**
- Wrap all of these in `text()`, or `attr()` for attributes.
- For the plan, use `nl2br(text($plan))`.

## 6. Unsafe variable variables / `extract()` (mass assignment)

**Location:**
- `$$LOCATION = text($prefs['GOVALUE']);` at top level, so it runs in the includer's global scope.
- `@extract($objQuery)` and `@extract($encounter_data)`.
- `$$key=$value` in `left_overs()`.

**Category:** A04 Insecure Design / A08 Data Integrity

**Severity:** Medium

**Problem:**
- `LOCATION` comes from the user-writable prefs table. A pref row named `pid`, `PDF_OUTPUT`, `srcdir`, `ar` or similar overwrites arbitrary globals in `custom_report.php`. That can change which patient is reported or reach the injection sinks above.
- `extract()` of `form_encounter.*` and `form_eye_mag.*` also silently overwrites function parameters such as `$pid`, `$encounter` and `$form_id`.

**Fix:**
- Store prefs in an associative array (`$prefs[$LOCATION]`) with a whitelist.
- Access row fields as `$row['FIELD']`, or use `extract($row, EXTR_SKIP)` with an explicit field list.

## 7. No authorization checks in the form report itself

**Location:** The entire file. There is no `acl_check` despite including `acl.inc`.

**Category:** A01 Broken Access Control

**Severity:** Medium

**Problem:**
- The script can be reached directly, and from the encounter-history mouseover (`choice`).
- It renders full clinical data and photos with no permission check.
- It also does not verify that the requested form belongs to the requested encounter and patient. `eye_mag_report`'s query also omits `forms.deleted`, so deleted forms are shown.

**Fix:**
- Add `acl_check('encounters', ...)` / `acl_check('patients','med')`.
- Validate ownership of the encounter and form, and filter out deleted forms.

## 8. Server filesystem path disclosure

**Location:** `echo "<img src='". $from_file."'..."` for the patient photo and drawings in PDF mode. Also the signature path `$GLOBALS["webserver_root"]...sign_".$providerID.".jpg`.

**Category:** A05 Security Misconfiguration

**Severity:** Low

**Problem:** Absolute server paths end up in the generated HTML or PDF.

**Fix:** Acceptable only for html2pdf. Ensure this output never reaches the browser (non-PDF output), and escape it with `attr()`.
