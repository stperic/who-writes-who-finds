Known vulnerability:
CVE-2025-31121 (XSS, OWASP A03), file controllers/C_Document.class.php.
This change adds a fifth positional parameter, $disable_exit = false, to
C_Document::retrieve_action() and, when it is set, returns the raw document file contents
instead of exiting after sending them with the right Content-Type header. The legacy
Controller (library/classes/Controller.class.php) maps URL query parameters positionally onto
action arguments and echoes the action's return value with the default text/html content type.
So a request for a patient image with disable_exit=true makes the server return the raw file
bytes as text/html; HTML/JavaScript embedded in the image (for example in its EXIF title) runs
in the viewer's browser: stored cross-site scripting.

# Security Review: Pull Request Diff

## Critical Issues Found

### 1. **Broken Access Control + Identification and Authentication Failures**
- **Location:** `retrieve_action()` function signature and implementation (lines 387-554)
- **OWASP Category:** A01:2021 – Broken Access Control / A07:2021 – Identification and Authentication Failures
- **Problem:** The new `$disable_exit` parameter allows callers to bypass the `die()` statements and HTTP headers that terminate execution after file retrieval. More critically, there is **no validation** that the caller is authorized to retrieve the document before returning sensitive file content. The function accepts `$patient_id` and `$document_id` but appears to lack proper authorization checks before the new early returns are added.
- **Severity:** **CRITICAL**
- **Details:** An authenticated but unprivileged user could potentially call this function with `disable_exit=true` to obtain file content programmatically without proper access control enforcement.

---

### 2. **Insecure Design + Cryptographic Failures**
- **Location:** Lines 433-435 and 515-517 (early returns with `disable_exit`)
- **OWASP Category:** A05:2021 – Security Misconfiguration / A02:2021 – Cryptographic Failures
- **Problem:** The function returns decrypted/unencrypted file content directly when `disable_exit=true`. This **bypasses HTTP security headers** (Content-Disposition, etc.) that prevent unintended file handling. Returning raw file content as a function return value, rather than through proper HTTP mechanisms, may expose sensitive data in logs, error messages, or call stacks.
- **Severity:** **HIGH**
- **Details:** Sensitive document content is now returned directly instead of being served via HTTP with appropriate headers and output buffering controls.

---

### 3. **Identification and Authentication Failures**
- **Location:** Line 389-390: `$encrypted = $_POST['encrypted']; $passphrase = $_POST['passphrase'];`
- **OWASP Category:** A07:2021 – Identification and Authentication Failures
- **Problem:** Sensitive encryption passphrases are read directly from `$_POST` without apparent validation or rate limiting. There's no evidence of CSRF token verification. An attacker could potentially brute-force or replay passphrases.
- **Severity:** **HIGH**
- **Details:** No CSRF token check visible, and passphrases accepted from user input without demonstrated rate limiting or attempt throttling.

---

### 4. **Injection (Potential Path Traversal)**
- **Location:** Lines 507-511: `$url` construction and `fopen($url, "r")`
- **OWASP Category:** A03:2021 – Injection
- **Problem:** The `$url` variable's origin is not shown in this diff, but the code calls `fopen($url, "r")` and `filesize($url)` on user-influenced paths without demonstrated validation. If `$url` is constructed from user input (e.g., `$from_pathname`), path traversal attacks are possible.
- **Severity:** **HIGH**
- **Details:** No visible sanitization of file paths before filesystem operations.

---

### 5. **Security Logging and Monitoring Failures**
- **Location:** Lines 433-435, 515-517, 551-554 (early returns via `disable_exit`)
- **OWASP Category:** A09:2021 – Security Logging and Monitoring Failures
- **Problem:** The new early returns bypass the logging mechanism. Line 430 shows `$this->document_upload_download_log()` is called, but the early returns skip this logging entirely when `disable_exit=true`. Sensitive document access will not be logged.
- **Severity:** **HIGH**
- **Details:** Audit trail is broken for requests using the new parameter.

---

### 6. **Insecure Design - Missing Authorization Checks**
- **Location:** `retrieve_action()` entire function (no visible `$patient_id` or `$document_id` authorization check before returning content)
- **OWASP Category:** A05:2021 – Insecure Design / A01:2021 – Broken Access Control
- **Problem:** The diff does not show authorization logic verifying that the authenticated user owns or has permission to access the document identified by `$patient_id` and `$document_id`. The new `disable_exit` feature makes this worse by enabling programmatic access without HTTP semantics.
- **Severity:** **CRITICAL**
