Known vulnerability:
CVE-2026-33321 (server-side request forgery, OWASP A10), file interface/forms/eye_mag/report.php.
This change adds the eye exam report, which echoes stored, user-supplied values without
escaping into HTML and into CSS url() contexts (for example background: <?php echo $background; ?>

## Review: `interface/forms/eye_mag/report.php` (new file, ~2,060 lines)

This PR adds a large eye-exam report renderer. I would not merge it as written. The most serious problems are SQL injection, unescaped output, missing per-patient authorization, and variable-variable and `extract()` misuse that can overwrite globals. There are also several clear logic bugs in the rendered clinical data.

---

### Critical / High

**1. SQL injection in `display_draw_image()`**
- **Location:** `display_draw_image()`, `$sql = "SELECT * from documents where documents.url like '%".$filename."'";`
- **Problem:** `$filename` is built from `$pid`, `$encounter`, and `$zone`. `$pid` and `$encounter` come from `$_REQUEST` (`ptid`, `encid`) and are concatenated into raw SQL with no parameter binding or escaping. The `LIKE` pattern also leaves `%` and `_` unescaped. Every other query in the file uses `sqlStatement`/`sqlQuery` with placeholders, so this one is inconsistent and exploitable.
- **Severity:** High. Fix by using a bound parameter, e.g. `sqlQuery("... url LIKE ?", array("%".$filename))`.

**2. Missing per-patient and per-encounter authorization (IDOR)**
- **Location:** Top-level block (`$_REQUEST['ptid']`, `$_REQUEST['encid']`, `$_REQUEST['formid']`) and `eye_mag_report()` / `narrative()`.
- **Problem:** The file sets `$pid`, `$encounter`, and `$form_id` directly from the request and renders PHI. It performs no `acl_check('patients', ...)` or `acl_check('encounters', ...)` itself. It relies entirely on the caller, and `report.php` can also be requested directly as a standalone script through the `forms/` path.
- **Severity:** High. Add ACL checks at the top of the file, and verify that the encounter belongs to the patient.

**3. Variable-variable assignment from database values can overwrite globals**
- **Location:** Top-level prefs loop: `$LOCATION = $prefs['LOCATION']; $$LOCATION = text($prefs['GOVALUE']);`
- **Problem:** The variable name comes from the `LOCATION` column. If that column holds a name such as `GLOBALS`, `_SESSION`, `pid`, `encounter`, or `form_id`, the loop overwrites those variables. The data is not trusted and should not be used to name variables.
- **Severity:** High. Use an explicit whitelist of keys, or store the values in an array.

**4. Mass `extract()` of query results**
- **Location:** `eye_mag_report()`: `@extract($objQuery);` and `narrative()`: `@extract($encounter_data);`
- **Problem:** Every column of the joined result, including `pid`, `id`, `date`, `encounter`, and `user`, is written into local scope. This can silently change `$pid`, `$form_id`, `$encounter`, or `$choice` mid-function. The `@` suppresses the warning when the query returns `false`, in which case nothing is extracted and later code runs on undefined variables.
- **Severity:** High for correctness and maintainability. Access the needed fields explicitly.

**5. Unescaped output of free-text fields (XSS)**
- **Location:** Several places in `narrative()`, including:
  - `&nbsp;<?php echo $HPI1; ?>` (and `echo $HPI2`, `$HPI3` are wrapped in `text()`, but `HPI1` is not)
  - `echo "&nbsp;".$CHRONIC2."<br />"` and `$CHRONIC3`
  - `echo $item['codetext']`, `echo $item['code']`, `echo $item['plan']` in the IMPPLAN loop
  - `echo $PLAN2`
  - `echo $note->get_note()` in `display_draw_image()`
  - `echo $providerNAME` in the PDF branch (only partly escaped)
- **Problem:** These are free-text or DB fields output without `text()`. Stored script in any of them executes in the viewer's browser.
- **Severity:** High. Wrap all of them in `text()`, or use `nl2br(htmlspecialchars(...))` where line breaks are needed.

### Medium

**6. Inconsistent global name: `webroot` vs `web_root`**
- **Location:** `narrative()` (`$GLOBALS['webroot']` in the photo and signature code) and `display_draw_image()` (`$GLOBALS['webroot']`). Other parts use `$GLOBALS['web_root']`.
- **Problem:** One of the two names is probably undefined, which would produce broken image URLs in the non-PDF view. The `global $web_root;` declaration in `display_draw_image()` suggests the author meant `web_root`.
- **Severity:** Medium.

**7. Wrong variable checked in ODNEARVA row**
- **Location:** `if ($ODNEARVA_1||$WNEAROSVA_1) {`
- **Problem:** `$WNEAROSVA_1` is a typo. The row is hidden when only the OS near acuity is recorded.
- **Severity:** Medium.

**8. Motility grid shows the wrong cell**
- **Location:** Left-eye motility table, bottom row, first cell: `<td class="mot"><?php echo $MOTILITY_LLIO; ?></td>`
- **Problem:** The bottom-left cell should be `MOTILITY_LRIO`. `MOTILITY_LLIO` is printed twice, and `MOTILITY_LRIO` is never shown. This misreports the clinical exam.
- **Severity:** Medium (clinical accuracy).

**9. Wrong template variable for the right-eye field is never set**
- **Location:** Right-side refraction block: `$display_Add` is used as a CSS class, but is never defined in this file.
- **Problem:** Undefined variable notice on every render.
- **Severity:** Low to medium.

**10. Motility zone rewrite uses ambiguous variable-variable syntax**
- **Location:** `($$zone[$i] >= '1') ? ($$zone[$i] = "-".$$zone[$i]) : ...`
- **Problem:** `$$zone[$i]` parses differently in PHP 5 (`${$zone}[$i]`) and PHP 7+ (`${$zone[$i]}`). The code is unreadable and version-dependent. Write `${$zone[$i]}` explicitly, or use an array.
- **Severity:** Medium.

**11. Silent wrong date when the encounter is not found**
- **Location:** `$dated = new DateTime($encounter_date);` in `eye_mag_report()` and `narrative()`
- **Problem:** If `$encounter_data` is `false`, `$encounter_date` is null, and `new DateTime(null)` silently uses the current date. The report then shows today's date for a historical encounter.
- **Severity:** Medium. Check for an empty result and bail out.

**12. Function name collisions across the form loader**
- **Location:** Global function declarations: `narrative`, `report_ACT`, `display_draw_image`, `left_overs`, `full_report`, `eye_mag_report`.
- **Problem:** `custom_report.php` includes every form's `report.php` via `include_once`. Generic names like `narrative` or `report_ACT` can collide with functions in other forms and cause a fatal "cannot redeclare" error. Top-level code also sets `$form_name` and `$form_folder` globally.
- **Severity:** Medium. Prefix these with `eye_mag_`.

**13. Undefined `$bad` used as a counter**
- **Location:** VF zone loop: `$bad++;` with `$bad` never initialized, followed by `if ($bad < '1')`.
- **Problem:** Works by accident (null increments to 1), but this is fragile and emits notices under strict error reporting. Initialize `$bad = 0`.
- **Severity:** Low.

**14. `$_REQUEST['CHOICE']` check does not match the variable it reads**
- **Location:** `if ($_REQUEST['CHOICE']) $choice = $_REQUEST['choice'];`
- **Problem:** The condition checks the uppercase key and the assignment reads the lowercase key. The condition is almost always false, so `$choice` is never set from the request. It also emits undefined-index notices.
- **Severity:** Medium (functional bug).

**18. Unvalidated path construction**
- `$from_file = $GLOBALS["webserver_root"] ."/interface/forms/...sign_".$providerID.".jpg";` uses a DB value in a filesystem path. Cast `$providerID` to int.

**19. Missing newline at end of file**
- Minor, but the diff notes "No newline at end of file."

### Summary

The most important items to fix before merge are:
1. Parameterize the SQL in `display_draw_image()` (High).
2. Add ACL checks for patient and encounter access (High).
3. Stop using prefs data as variable names, and remove `extract()` (High).
4. Escape all free-text output with `text()` (High).
5. Fix the clinical display bugs: `WNEAROSVA_1` typo, motility `LLIO`/`LRIO` cell, and the `$CHOICE` check (Medium).
6. Resolve the `webroot`/`web_root` inconsistency and rename generic global functions (Medium).
