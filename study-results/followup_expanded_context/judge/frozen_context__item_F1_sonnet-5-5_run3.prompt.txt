Known vulnerability:
Advisory GHSA-9rj4-fxmj-c4r7 (severity high), file library/classes/Controller.class.php.
This change adds Controller::dispatch(), a VALID_CONTROLLERS whitelist and a CONTROLLER_ACL_MAP.
checkControllerAcl() returns without any check when a controller has no CONTROLLER_ACL_MAP entry,
and the map only covers practice_settings and prescription. Sub-controllers in VALID_CONTROLLERS
(pharmacy, insurance_company, insurance_numbers, x12_partner, document_category, hl7,
patient_finder, document) are therefore directly reachable by any authenticated user with no
permission check. They were meant to be reached only through practice_settings, which requires
admin/practice. Impact: a low-privilege user can rewrite x12_partner insurance claim-routing
credentials (SFTP host/login/password, API client secrets) and enumerate every patient through
patient_finder. The same gap existed before this change through the legacy positional routing;
this change carried it into the new dispatcher without closing it.

Review to score:
<review>
Here is what I found, roughly in order of severity.

**1. Medium–High: `dispatch()` drops the `method_exists()` check, so the "action not found" path is effectively dead.**
- Location: `dispatch()`, the `is_callable([$controllerObj, $processMethod])` and `is_callable([$controllerObj, $actionMethod])` checks.
- The old code had a comment explaining that Smarty 4's `__call` makes `is_callable()` always true, so it also checked `method_exists()`. The new code drops that and relies on `is_callable()` alone.
- Result: for a nonexistent action, `is_callable` returns true and the call goes into Smarty's `__call`, which throws a `SmartyException` ("Undefined method"). The intended `NotFoundHttpException` is never thrown, so the user gets a 500 instead of a 404.
- In process mode, a missing `*_action_process` is also "callable", so the process step is attempted on controllers that don't define it.
- Fix: restore `method_exists() && is_callable()`. In process mode, also don't call the action method unconditionally.

**2. Medium: the `_state` comparison changed from `==` to `===`.**
- Location: `dispatch()`, `if ($controllerObj->_state === false)`.
- `_state` is declared without a default, so it is `null`. The old `null == false` returned early after the process step. The new strict check continues on and runs the main action.
- This changes behaviour for any controller whose process handler doesn't set `_state` explicitly. It needs auditing, or the loose comparison should be kept.

**3. Medium: the `action` value is no longer sanitized.**
- Location: `dispatch()`, `$action = $params['action']`, followed by `$controllerObj->_current_action = $action`.
- The old code stripped everything except `[A-Za-z0-9_]`. Now arbitrary user input is stored in `_current_action`, which `_link()` and templates may echo, so this is a possible XSS vector.
- It also lets callers choose any method ending in `_action`. Restore sanitization or validate against `^[A-Za-z0-9_]+$`.

**4. Medium: an empty `action` no longer falls back to `default`.**
- Location: `dispatch()`, where `$action` is built.
- `?action=` gives an empty string, which passes `is_string` and produces the method name `_action`. The old code mapped empty to `default`. Use `$params['action'] === '' ? 'default' : ...`.

**5. Medium: uncaught exceptions replace the old echo-and-exit behaviour.**
- Location: `dispatch()`, the `BadRequestHttpException` and `NotFoundHttpException` throws.
- `controller.php` is the legacy entry point and I can't see whether it catches these. If it doesn't, users get a fatal error or a stack trace, which could leak paths.
- Confirm there is a handler, or have `controller.php` convert them into proper responses.

**6. Medium: `act()` can fail on empty input, and its key comparison is unsafe.**
- Location: `act()`.
- With an empty `$qarray`, `$keys[0]` triggers an undefined-index warning and then a `BadRequestHttpException`. The `non-empty-array` docblock is not enforced, and the old code tolerated this.
- `$key === $controller` compares an int array key against a string cast. For numeric-like keys the positional params won't be skipped, so they leak into the args.
- Extra query keys named `controller` or `sub_action` overwrite or collide with routing params. `controller=...` in the query string can override the positional controller. Only `action` is renamed, so `controller` should be treated as reserved too.

**7. Low–Medium: argument handling differs from the old code.**
- Location: `dispatch()`, the args loop.
- Arguments are now taken in `$params` iteration order, not in the explicit order the legacy code used. This is fine for `act()`, but it silently depends on caller key order. That undermines the "order-independent routing" claim in the docblock.
- Only `''` is converted to `null`. The old `empty() && != "0"` also converted `null`, `false` and `[]`.
- `$callMethod` silently discards non-string return values with `is_string(...) ? ... : ''`, where the old code concatenated them. This can hide bugs.

**8. Low: the `process` flag handling is odd.**
- Location: `dispatch()`.
- It unsets `$_GET['process']` based on `$params`, which is only coincidentally the same source.
- A GET parameter still forces `$_POST['process'] = "true"`. This existed before, but it is worth flagging as a CSRF-style concern.

**9. Low: the whitelist and ACL map are duplicated and static.**
- Location: `VALID_CONTROLLERS` and `CONTROLLER_ACL_MAP`.
- The two maps are separate, so a new controller needing ACL can be added to one and not the other.
- The whitelist may also omit controllers that previously loaded dynamically from `controllers/`. Verify that no other `C_*.class.php` files are reached through `controller.php`.
- Controllers other than `practice_settings` and `prescription` still have no ACL check, as before.

**10. Low: there are no tests for the new routing.**
- A change to a central dispatcher with behaviour changes (items 1–4) should come with tests covering legacy `act()`, `dispatch()`, the process flow and the error paths.
</review>
