Known vulnerability:
CVE-2025-31121 (XSS, OWASP A03), file controllers/C_Document.class.php.
This change adds a fifth positional parameter, $disable_exit = false, to
C_Document::retrieve_action() and, when it is set, returns the raw document file contents
instead of exiting after sending them with the right Content-Type header. The legacy
Controller (library/classes/Controller.class.php) maps URL query parameters positionally onto

So a request for a patient image with disable_exit=true makes the server return the raw file
bytes as text/html; HTML/JavaScript embedded in the image (for example in its EXIF title) runs
in the viewer's browser: stored cross-site scripting.

## Security review of `C_Document::retrieve_action` changes

The diff adds a `$disable_exit` flag so that callers can receive file contents as a return value instead of streaming them to the client. The flag introduces some new risk, and the function it modifies has several older flaws.

### Issues introduced or worsened by this change

**1. Caller-controllable `$disable_exit` on a controller action**
- **Location:** the new `$disable_exit=false` parameter and the three `if($disable_exit == true) return …` branches.
- **OWASP:** A04 Insecure Design / A05 Security Misconfiguration
- **Problem:** `retrieve_action` is a web-reachable controller action. OpenEMR's controller dispatcher passes query-string values to action methods positionally. A remote user can therefore set `disable_exit` themselves, and nothing restricts the flag to internal callers. Setting it only suppresses output, so the direct impact is small. But the early returns skip the rest of the function, which may include post-processing or audit logging after the download. The flag also turns an action that "sends a file" into one that "returns decrypted file bytes to arbitrary PHP callers", and those callers must now enforce their own authorization.
- **Fix:** Move the file-reading logic into a separate non-action method, for example `get_document_contents()`, that is not routable. Keep `retrieve_action` unchanged.
- **Severity:** Low to Medium

**2. Whole file read into memory on every request, with no error handling**
- **Location:** `$f = fopen($url,"r"); $filetext = fread($f, filesize($url));`, which was moved out of the `$doEncryption` branch.
- **OWASP:** A04 Insecure Design / A05 Security Misconfiguration
- **Problem:**
  - Previously the entire file was loaded only when encrypting. Now every download loads it fully, so large documents can exhaust memory (DoS).
  - The `fopen` result is never checked, and the handle is never closed.
  - `fread` with a length of 0 (an empty file) or a `false` handle fails or warns, which can leak filesystem paths through error output.
- **Fix:** Check that the file exists and is readable. Stream it with `readfile` or `fpassthru`. Close the handle. Use `file_get_contents` only in the internal-return path.
- **Severity:** Low to Medium

**3. Audit logging may be bypassed on the new return paths**
- **Location:** all three `$disable_exit` early returns.
- **OWASP:** A09 Security Logging and Monitoring Failures
- **Problem:** The CouchDB path logs failures through `document_upload_download_log`. It is not visible that a successful retrieval is logged before any of the new returns. If logging happens after the return points, document access (PHI) via this path is unaudited.
- **Fix:** Log the access before returning, in every path.
- **Severity:** Medium (the code is an EMR, so PHI access auditing is a regulatory requirement)

### Pre-existing flaws in the code this change touches

**4. Possible IDOR / missing authorization**
- **Location:** the signature `retrieve_action($patient_id, $document_id, …)`.
- **OWASP:** A01 Broken Access Control
- **Problem:** The diff shows no check that `$document_id` belongs to `$patient_id`. The log call uses `$d->get_foreign_id()`, not the requested patient, which suggests the two are not tied together. It also shows no per-document ACL check. A user who is authorized for one patient could enumerate `document_id` values to read other patients' records. The new return-value mode makes this worse if other code calls it without its own checks.
- **Severity:** High (if the checks are indeed missing elsewhere in the function)

**5. `fopen($url)` on a database-derived path**
- **Location:** `fopen($url,"r")` and the `$url` construction.
- **OWASP:** A10 SSRF / A01 (path traversal) / A03
- **Problem:** `$url` comes from the document record. It is opened without checking the scheme or that the resolved path is inside the documents directory. If an attacker can influence a document's URL (through upload or edit paths), this allows local file inclusion with `file://` or `../`. With `allow_url_fopen`, it also allows SSRF through `http://` or `ftp://`.
- **Fix:** Use `realpath()` and enforce that the result is under `$GLOBALS['OE_SITE_DIR'].'/documents'`. Reject any URL containing a scheme.
- **Severity:** Medium

**6. Passphrase and encrypted-download handling**
- **Location:** `$_POST['passphrase']`, `$this->encrypt(...)`, and the temp file `"/encrypted_".$d->get_url_file()`.
- **OWASP:** A02 Cryptographic Failures
- **Problem:**
  - The encrypted output is written to the shared temp directory under a predictable, filename-derived name. Concurrent requests can collide, and the file may be readable by other users or left behind.
  - The passphrase is sent as a user-supplied POST value, and the strength of the `encrypt` implementation is unknown.
  - `$_POST['encrypted']` is used without validation.
- **Fix:** Use `tempnam()` with restrictive permissions, delete the file after sending, and use an authenticated cipher (AES-GCM).
- **Severity:** Medium

**7. HTTP header injection / content sniffing**
- **Location:** the `header(...)` calls that use the stored file name and MIME type.
- **OWASP:** A03 Injection / A05 Security Misconfiguration
- **Problem:** If the stored file name or MIME type is placed in `Content-Disposition` or `Content-Type` unsanitized, a user-uploaded HTML or SVG file could be served inline from the application origin, leading to stored XSS. Newer PHP versions block CR/LF header injection.
- **Fix:** Sanitize and quote the file name, send `X-Content-Type-Options: nosniff`, and force `attachment` for risky types.
- **Severity:** Medium

### Non-security note
The converted-file branch does `return ;`, so callers with `$disable_exit` set get `null`. This is a functional bug, not a vulnerability.

### Summary
The most important actions before merging are:
1. Make the new behavior non-routable, by moving it out of the controller action or ignoring the flag when it comes from the request.
2. Confirm that authorization and audit logging happen on all return paths.
3. Fix the path validation and memory handling around `fopen`/`fread`.
