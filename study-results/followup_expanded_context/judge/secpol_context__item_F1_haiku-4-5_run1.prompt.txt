# Security Review of Pull Request

## Summary
This PR refactors the controller routing logic in OpenEMR, replacing positional parameter parsing with explicit parameter-based dispatch. While the refactoring improves code maintainability, **several significant security issues** are present.

---

## Critical Issues Found

### 1. **Broken Access Control - Double ACL Check Vulnerability**
**Location:** `Controller.class.php` lines 107-127 (new `checkControllerAcl()`) and `C_PracticeSettings.class.php` constructor

**OWASP Category:** Broken Access Control (A01:2021)

**Problem:** The `practice_settings` controller implements ACL checks in two places:
1. In the new `dispatch()` method via `checkControllerAcl()`
2. In `C_PracticeSettings` constructor

However, the `C_PracticeSettings` constructor check can be **bypassed** when controllers delegate to sub-controllers. The `pharmacy_action()`, `insurance_company_action()`, and similar methods call `dispatch()` directly with specific sub-controller names. If an attacker crafts a request like `controller=practice_settings&action=pharmacy&...`, the initial ACL check passes, but then calling `pharmacy_action()` invokes `dispatch()` with `controller=pharmacy`, which **lacks an ACL mapping** and therefore bypasses any authorization check for that sub-action.

**Severity:** **HIGH**

**Recommendation:** 
- Ensure all controllers and sub-controllers have explicit ACL mappings in `CONTROLLER_ACL_MAP`
- Add ACL checks for: `pharmacy`, `insurance_company`, `insurance_numbers`, `document`, `document_category`, `x12_partner`, `hl7`

---

### 2. **Injection - Unsafe Variable Interpolation in Error Messages**
**Location:** `Controller.class.php` lines 156-158 (new `dispatch()` method)

**OWASP Category:** Injection (A03:2021)

**Problem:** User-controlled `$controllerParam` is directly interpolated into the exception message:
```php
throw new NotFoundHttpException("Missing or invalid 'controller' parameter");
```
While this specific instance is acceptable, the later error message at line 173:
```php
throw new NotFoundHttpException("Unable to load controller: $className");
```
uses `$className` which is derived from the whitelist, so this is safe. However, line 228 contains:
```php
throw new NotFoundHttpException("Action '$action' does not exist on controller: $className");
```
The `$action` parameter comes from user input (`$params['action']`) and is only checked with `is_string()`, not sanitized. This could be reflected in error responses.

**Severity:** **MEDIUM** (Limited impact due to exception handling, but still a concern)

**Recommendation:** Sanitize or escape `$action` in error messages, or avoid including user input in exceptions.

---

### 3. **Broken Access Control - Whitelist Not Comprehensive**
**Location:** `Controller.class.php` lines 20-29 (new `VALID_CONTROLLERS` constant)

**OWASP Category:** Broken Access Control (A01:2021)

**Problem:** The whitelist is incomplete. Controllers like `pharmacy`, `insurance_company`, `insurance_numbers`, `document`, `document_category`, `x12_partner`, and `hl7` are referenced in the context file but are not in `VALID_CONTROLLERS`. This means:
- These controllers cannot be directly accessed via `dispatch(controller=pharmacy, ...)`
- However, they *can* be accessed through the `practice_settings` sub-actions
- This creates an inconsistent security model where some endpoints are protected by the whitelist and others are protected by sub-controller delegation

**Severity:** **MEDIUM**

**Recommendation:** Add all controllers referenced in `C_PracticeSettings` to the whitelist, or document why they intentionally remain unwhitelisted.

---

### 4. **Broken Access Control - Missing Input Validation on Action Parameter**
**Location:** `Controller.class.php` lines 198-201 (new `dispatch()` method)

**OWASP Category:** Broken Access Control (A01:2021)

**Problem:** The `action` parameter is only checked with `is_string()` but is **not validated against a whitelist**. This allows calling arbitrary public methods on controller classes:
```php
$action = is_string($params['action'] ?? null) ? $params['action'] : 'default';
$actionMethod = "{$action}_action";
```
An attacker could potentially call unintended methods like `admin_action`, `debug_action`, etc., if they exist on the controller. The method name is only checked with `is_callable()` after construction, which is insufficient.

**Severity:** **HIGH**

**Recommendation:** 
- Implement a whitelist of allowed action names per controller
- Or validate that action names match a safe pattern (e.g., `[a-z0-9_]+`)

---

### 5. **Broken Access Control - ACL Check Only on Specific Controllers**
**Location:** `Controller.class.php` lines 34-38 (new `CONTROLLER_ACL_MAP` constant)

**OWASP Category:** Broken Access Control (A01:2021)

**Problem:** Only `practice_settings` and `prescription` controllers have ACL mappings. All other controllers pass through without ACL checks. The code at line 111 silently returns if a controller is not in the map:
```php
if (!isset(self::CONTROLLER_ACL_MAP[$controllerName])) {
    return;  // No ACL check for this controller!
}
```

This is a **dangerous default**. Controllers like `document`, `patient_finder`, `hl7`, etc., have no access control whatsoever at the dispatch layer.

**Severity:** **HIGH**

**Recommendation:** 
- Require explicit ACL mappings for all controllers, or
- Implement a default deny policy with an opt-out mechanism, or
- Move ACL checks into each controller's constructor (which `C_PracticeSettings` already does, but others may not)

## Low/Medium Issues

### 6. **Insecure Design - Error Information Disclosure**
**Location:** `Controller.class.php` lines 172-173, 228

**OWASP Category:** Insecure Design (A04:2021)

**Problem:** Exceptions throw detailed error messages including controller and action names, which could leak information about the application's structure:
```php
throw new NotFoundHttpException("Unable to load controller: $className");
throw new NotFoundHttpException("Action '$action' does not exist on controller: $className");
```

**Severity:** **LOW** (Information disclosure is typically low-severity in routing contexts)

**Recommendation:** Consider returning generic error messages in production or logging detailed errors server-side.

---

### 7. **Potential Issue - Method Dispatch Without Explicit Checks**
**Location:** `Controller.class.php` lines 212-218 (new `dispatch()` method)

**OWASP Category:** Broken Access Control (A01:2021)

**Problem:** The code uses `is_callable()` and `method_exists()` but does not prevent calling private or protected methods:
```php
if ($isProcessing && is_callable([$controllerObj, $processMethod])) {
```

If a controller accidentally defines a private `some_action_process()` method, it could still be called through reflection. While PHP's visibility enforcement prevents this at runtime, relying on method visibility for security is fragile.

**Severity:** **LOW** (PHP's visibility enforcement prevents actual exploitation)
