Known vulnerability:
CVE-2026-33321 (server-side request forgery, OWASP A10), file interface/forms/eye_mag/report.php.
This change adds the eye exam report, which echoes stored, user-supplied values without
escaping into HTML and into CSS url() contexts (for example background: <?php echo $background; ?>
and free-text fields such as HPI, motility, visual field, Rx type and plan/order details). The
patient report page renders forms' report.php output server-side into a PDF with an HTML-to-PDF
renderer, which fetches URLs in the markup. Injected URLs are therefore fetched by the server:
out-of-band server-side request forgery. The root cause is the missing output escaping; the
same flaw also allows HTML injection in the browser view.

# Code review: `interface/forms/eye_mag/report.php`

## Critical / High: security

**1. SQL injection in `display_draw_image()`**
- `$sql = "SELECT * from documents where documents.url like '%".$filename."'";`
- `$filename` is built from `$pid` and `$encounter`.
- At the top of the file those can be overwritten straight from `$_REQUEST['ptid']` and `$_REQUEST['encid']`. The value reaches the query unsanitized.
- **Fix:** use a bound parameter.
- **Severity: Critical**

**2. Cross-patient document disclosure via LIKE matching (same query)**
- The pattern has a leading `%`, and `_` is a LIKE wildcard.
- So `'%1_123_OU_EXT_VIEW.jpg'` also matches `11_123_…`, `21_123_…`, `1x123…`, and so on.
- Patient A's report can therefore render patient B's drawings.
- **Fix:** match on exact URL or `foreign_id`, filter by `pid`, and escape wildcards.
- **Severity: High (PHI leak)**

**3. Unauthenticated override of patient/encounter context, with no ACL check**
- `$pid`, `$encounter`, `$form_id` and `$form_name` are taken from `$_REQUEST` (`ptid`, `encid`, `formid`, `formname`).
- There is no `acl_check()` anywhere in the file.
- Any logged-in user can render any patient's full exam by changing the URL (IDOR).
- **Severity: High**

**4. Stored XSS: many DB fields echoed without `text()`/`attr()`**
- `$HPI1` (the other HPIs are escaped).
- `$CHRONIC2`, `$CHRONIC3`.
- `$CTLOSVA`.
- All motility values `$MOTILITY_*`.
- In the IMPPLAN block:
  - `$item['codetext']`, `$item['code']`, `$item['plan']`. The plan is `str_replace`d to `<br />` and printed raw; it should be escaped first, then newlines converted.
  - `$PLAN` items and `$PLAN2`.
- `$note->get_note()` in `display_draw_image()`.
- `$providerNAME` in the PDF signature line.
- `$from_file` / `$filetoshow` in `<img src>`. These include `$pid` from `$_REQUEST`, which also makes them reflected XSS.
- `$form_folder` in the Amsler `<img src>`.
- **Severity: High**

**5. String-concatenated SQL**
- `"select * from facility where id=" . $_SESSION['pc_facility']`
- The value comes from the session, but this should still be parameterized.
- **Severity: Medium**

**6. `@extract($objQuery)` / `@extract($encounter_data)`**
- These dump every column of `form_encounter.*` and `form_eye_mag.*` into local scope, with errors suppressed.
- Columns such as `pid`, `encounter`, `id`, `provider_id`, `form_id` silently overwrite function parameters and locals. Any future column whose name collides with a local variable (e.g. `choice`, `cols`) will change behaviour.
- **Fix:** access the result array explicitly.
- **Severity: Medium**

**7. `$$LOCATION = text($prefs['GOVALUE']);` at global scope**
- These are DB-driven variable variables. They can clobber any global, including `$pid`, `$encounter` and `$GLOBALS` config.
- They are also HTML-escaped at assignment, which risks double-escaping later.
- **Severity: Medium**

## High: correctness

**8. `$choice` is never set**
- `if ($_REQUEST['CHOICE']) $choice = $_REQUEST['choice'];` checks `CHOICE` but reads `choice`. The key case is inconsistent.

**9. Choice dispatch logic is inverted**
- `else if ($choice != "narrative")` means `choice=narrative` renders nothing.
- The doc block says narrative/absent should display everything.
- It also documents `NARRATIVE` (uppercase) while comparing lowercase.

**10. Short open tags `<?`**
- They appear after the `CC2` block and in the commented DRAW code.
- With `short_open_tag=Off`, the `<?` is emitted as literal text. The `}` inside it is no longer PHP, so the brace structure breaks and the file fails to parse.

**11. `$$zone[$i]` in the motility loop**
- PHP 7 parses this as `($$zone)[$i]`, not `${$zone[$i]}`.
- On PHP 7+ the motility values are never transformed. It may also raise array-to-string notices.
- **Fix:** use `${$zone[$i]}`.

**12. Wrong motility cell**
- The left-eye bottom row prints `$MOTILITY_LLIO` twice.
- The first cell should be `$MOTILITY_LRIO`.
- This is clinically incorrect output.

**13. Queries don't filter `forms.formdir` and ignore the form id**
- Both encounter queries join `form_eye_mag.id = forms.form_id` without `forms.formdir='eye_mag'`. They can match another form type's row that happens to share the id.
- The first query (`eye_mag_report`) also lacks `forms.deleted` filtering.
- Neither query uses `$id`/`$form_id`, so with multiple eye_mag forms in one encounter an arbitrary one is shown.

**14. Typos in conditions that hide data**
| Location | Condition as written | Should be |
|---|---|---|
| ccNear row | `$ODNEARVA_1\|\|$WNEAROSVA_1` | `$OSNEARVA_1` |
| Gonioscopy | `$ODGONIO\|\|$OSDGONIO` | `$OSGONIO` |
| Additional data | `$PAMODBA` | `$PAMODVA` |
| NPC | `$ODNPC or $OSNPC` (then prints `$NPC`) | `$NPC` |

- Retina guard: `$ODDISC||$OSDISC||$ODCUP||$ODMACULA||$ODVESSELS||$ODPERIPH` omits the OS fields. Left-eye-only cup, macula, vessel or periphery findings are not reported.
- Refraction guard uses `$ODVA||$OSVA`, but the wearing Rx values live in `$ODVA_1` etc. Current glasses may not display.

**15. AR comments block uses the stale loop variable**
- It reads `${"COMMENTS_$i"}` after the Rx loop, where `$i == $count_rx+1`. The value is undefined or wrong.
- The "Comments:" label there is also untranslated.

**16. Character replacement corrupts UTF-8 in IMPPLAN `plan`**
- `"\x85"` replaces a single byte that occurs as a UTF-8 continuation byte (e.g. `…`, `Å`). This corrupts multibyte text.
- `"\u2028"` / `"\u2029"` are not escapes in PHP (PHP 7 needs `\u{2028}`), so they match the literal text "\u2028".

**17. Signature date is misleading**
- "electronically signed on" uses `oeFormatShortDate()`, which is today's date at render time, not the actual signing date.
- This is a medico-legal concern.
- **Severity: High (clinical record)**

**21. `$document_id > '1'` excludes document id 1**

**22. Missing `echo` loses the tooltip**

## Low: maintainability and i18n

**25. Inconsistent globals and paths**
- Mixes `$GLOBALS['web_root']`, `$GLOBALS['webroot']` and `global $web_root`.
- `eom.bmp` vs `eom.jpg`.
- The `<img heght=75>` typo appears in commented code.

**26. Massive copy/paste**
- The HPI ×3, refraction rows and ACT grids ×4 should be helper functions or loops.
- The near-identical document-path code appears twice.

**27. File ending**
- Trailing `?>` with no final newline; omit the closing tag to avoid stray output.

**Recommendation:** do not merge until 1–4, 8–14, and 17 are fixed.
