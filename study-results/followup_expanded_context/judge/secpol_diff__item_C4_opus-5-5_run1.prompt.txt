# Security Review: `interface/forms/eye_mag/report.php`

## Summary

This file should not be merged as written. It has:
- an unauthenticated-by-ACL patient-context override (IDOR),
- a request-driven SQL injection,
- widespread stored and reflected XSS of PHI fields,
- several insecure-design issues: variable-variable injection, `extract()`, and publicly served signature images.

## 1. Patient/encounter context overridable from the request (IDOR)

**Category:** A01 Broken Access Control. **Severity: High.**

```php
if ($_REQUEST['ptid']) $pid = $_REQUEST['ptid'];
if ($_REQUEST['encid']) $encounter=$_REQUEST['encid'];
if ($_REQUEST['formid']) $form_id = $_REQUEST['formid'];
if ($_REQUEST['formname']) $form_name=$_REQUEST['formname'];
```

**The problem:**
- This runs at global scope whenever the file is included, and it overwrites the session-bound `$pid` and `$encounter`.
- Report callers (encounter summary, `encounters_ajax.php`, custom reports, fax/taskman) include `*_report.php` and then call `eye_mag_report($pid, $encounter, …)` using these globals.
- Any authenticated user can therefore add `?ptid=X&encid=Y` and render another patient's full exam: HPI, PMSFH, photo, drawings, Rx and plan.
- Any code in the including page that runs after the include also operates on the attacker-chosen patient.
- `acl.inc` is included, but `acl_check()` is never called. There is no check that the user may access this patient's encounters or this form type.

**Fix:**
- Remove the overrides, or restrict them to a trusted internal caller.
- Cast the values to integers.
- Enforce `acl_check('patients','med')` (and encounter/sensitivity checks) before rendering.

## 2. SQL injection in `display_draw_image()`

**Category:** A03 Injection, with A01 consequences. **Severity: High/Critical.**

```php
$base_name = $pid."_".$encounter."_".$side."_".$zone."_VIEW";
$filename = $base_name.".jpg";
$sql = "SELECT * from documents where documents.url like '%".$filename."'";
$doc = sqlQuery($sql);
```

**SQL injection:**
- `$pid` and `$encounter` come directly from `$_REQUEST['ptid']` and `$_REQUEST['encid']` (issue 1).
- `$sanitize_all_escapes=true` disables OpenEMR's legacy auto-escaping, so the values reach the query unescaped.
- A payload such as `ptid=1' UNION SELECT ... -- ` allows arbitrary data extraction from the database, including the `users` table and password hashes.

**Even without injection, the LIKE pattern leaks other patients' documents:**
- The leading `%` means `pid=1, encounter=5` matches `…/11_5_OU_EXT_VIEW.jpg`, `21_5_…`, and so on.
- `_` is an unescaped LIKE wildcard.
- As a result, another patient's drawing (and its notes, which are output raw, see issue 3) can be displayed.

**Fix:**
- Use a bound parameter.
- Match on exact `foreign_id = ?` plus the exact URL suffix, with `_` and `%` escaped.

## 3. Stored XSS: PHI fields echoed without encoding

**Category:** A03 Injection (XSS). **Severity: High.**

Most fields correctly use `text()`, but the following are output raw:

| Location | Raw output |
|---|---|
| HPI line | `echo $HPI1;` (`HPI2`/`HPI3` are escaped, `HPI1` is not) |
| Chronic problems | `echo "&nbsp;".$CHRONIC2`, `echo "&nbsp;".$CHRONIC3` |
| Impression/Plan | `echo $item['codetext']`, `echo $item['code']` (with `codetype`), `echo $item['plan']` (only newline→`<br />` replacement) |
| Orders | `echo $item."<br />"` for each `explode('|',$PLAN)`, and `echo $PLAN2` |
| Contact lens | `echo ($CTLOSVA?:"-")` |
| Motility grid | `$$zone[$i] = "-".$$zone[$i]` then `echo $MOTILITY_*`. The check `>= '1'` passes for strings like `"1<script>…"`. |
| Drawing notes | `echo '<td>'.$note->get_note().'…'` |
| PDF signature block | `$providerNAME` (escaped a few lines later, but not here) |
| Additional data table | `$display_Add` in a class attribute (uninitialized and unescaped) |
| Image paths | `$form_folder` in image paths (constant today, but should be `attr()`) |

**Impact:**
- Any user who can edit an eye exam, problem list, or document note can plant script.
- That script runs in the session of every clinician or administrator who views the report or the encounter-history mouse-over, enabling session riding and PHI exfiltration.
- In PDF mode, injected HTML can also manipulate html2pdf, for example `<img src="/etc/...">` local file references.

**Fix:**
- Wrap every value in `text()`, or `attr()` for attributes.
- For multi-line fields use `nl2br(text($x))`.

## 4. Reflected XSS via `ptid`

**Category:** A03 Injection. **Severity: High.**

```php
$filetoshow = $GLOBALS['webroot']."/controller.php?document&retrieve&patient_id=$pid&document_id=...";
echo "<img src='".$filetoshow."' style='width:220px;'>";
```

**The problem:**
- In the patient photo block, the lookup is `documents.foreign_id=?` with `$pid = "1' onerror='alert(document.cookie)"`.
- MySQL's string-to-integer coercion matches patient 1, so a photo is found.
- The unencoded `$pid` then breaks out of the single-quoted `src` attribute.
- The same pattern occurs in `display_draw_image()`, where the row can be forced via issue 2.
- `$from_file` is likewise unencoded in PDF mode.

**Fix:**
- Cast `$pid` and `$encounter` with `(int)`.
- Build URLs with `attr()` and `urlencode()`.

## 5. Concatenated SQL with session value

**Category:** A03 Injection. **Severity: Medium.**

```php
$sql = "select * from facility where id=" . $_SESSION['pc_facility'];
```

**The problem:**
- `pc_facility` is populated from request data in the calendar module in several OpenEMR versions, so it is not a trustworthy integer.
- This is pre-existing code the change relies on.

**Fix:** use `sqlQuery("select * from facility where id=?", array($_SESSION['pc_facility']))`.

## 6. Variable-variable assignment from DB preferences

**Category:** A04 Insecure Design / A08 Data Integrity. **Severity: Medium.**

```php
$LOCATION = $prefs['LOCATION'];
$$LOCATION = text($prefs['GOVALUE']);
```

**The problem:**
- This executes at global scope, so any global variable named by a `form_eye_mag_prefs.LOCATION` row is overwritten.
- That includes `$pid`, `$encounter`, `$form_id`, `$PDF_OUTPUT`, `$GLOBALS` entries, and at global scope even superglobals such as `$_SESSION`.
- Preferences are user-writable through the eye_mag save endpoint, so a user can tamper with variables in their own request context. That can redirect `$pid` or influence the including page's logic.

**Fix:** store preferences in an array (`$prefs[$LOCATION] = …`) and whitelist the allowed keys.

## 7. `@extract()` of database rows

**Category:** A04 Insecure Design. **Severity: Low–Medium.**

**The problem:**
- `extract($encounter_data)` pulls in `form_encounter.*` and `form_eye_mag.*`, including columns such as `pid`, `encounter`, `id` and `provider_id`.
- Local variables used later for authorization-relevant queries (`$pid`, `$encounter`) are silently replaced with whatever column names exist.
- The `@` suppresses errors, so this happens without any warning.
- `left_overs()` does the same with `$$key=$value` on undefined `$table_name`/`$id`. It is dead code and should be removed.

**Fix:** access the row as an array, or call `extract()` with `EXTR_SKIP` and a prefix.

## 8. Provider e-signatures served from the web root

**Category:** A05 Security Misconfiguration / A01. **Severity: Medium.**

`images/sign_<providerID>.jpg` lives under `/interface/forms/eye_mag/images/` and is referenced directly by URL.

**The problem:**
- The provider IDs are sequential integers.
- Static files are served without OpenEMR authentication, so anyone can enumerate and download every provider's handwritten signature.

**Fix:** store signatures in the documents repository, outside the web root, and serve them through an authenticated controller.

## 9. Misleading electronic signature attestation

**Category:** A08 Software and Data Integrity Failures. **Severity: Medium.**

**The problem:**
- In PDF/fax mode, the signature image is printed with "electronically signed on `oeFormatShortDate()`", which is today's date.
- This happens whenever the image file exists, regardless of whether the encounter or form was actually signed or locked, or by whom.
- Faxed and exported documents can therefore falsely appear signed by the provider.

**Fix:** only render the attestation when an actual signature record exists (e.g. `esign_signatures`), using its signer and timestamp.

## 10. Weak query constraints

**Category:** A01 Broken Access Control. **Severity: Low.**

**`eye_mag_report()`:**
- It does not filter `forms.deleted`.
- It does not filter `forms.formdir='eye_mag'`.

**`narrative()`:**
- It joins `form_eye_mag.id=forms.form_id` without `formdir`.
- It does not tie `forms.pid` to the patient.
- Rows from deleted forms, or from an unrelated form whose numeric id collides, can therefore be shown.

**Impplan query:**
- It filters on the caller-supplied `$form_id` and `$pid` only.
- Combined with issue 1, this lets a user choose arbitrary form/patient pairs.

## 11. Logging and monitoring

**Category:** A09. **Severity: Low.**

**The problem:**
- Viewing a different patient via `ptid` bypasses the normal "set active patient" flow.
- No explicit audit event (e.g. `newEvent('view', …)`) is written for the patient actually displayed.
- This makes cross-patient snooping harder to detect in the access log.

---

## Recommended Remediation Order

1. Remove the `$_REQUEST` overrides, or cast them to `(int)` and add `acl_check` plus patient-access checks.
2. Parameterize and tighten the `documents` lookup in `display_draw_image()`, and parameterize the facility query.
3. Escape every output with `text()` or `attr()`, especially `HPI1`, `CHRONIC2/3`, IMPPLAN `code`/`codetext`/`plan`, `PLAN`/`PLAN2`, notes, motility values, `$pid` in URLs, and `CTLOSVA`.
4. Replace `$$LOCATION` and `extract()` with array access.
5. Move signature images out of the web root and tie the "electronically signed" text to real e-sign records.
6. Add an explicit PHI-view audit entry and remove dead code (`left_overs`, `full_report`).
