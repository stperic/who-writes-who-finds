# Security review: `Controller::act()` / `Controller::dispatch()` refactor

The refactor has real improvements. Controller names are now checked against a whitelist, the filesystem path is built from a constant map rather than user input, and the ACL map is centralised. The findings below are regressions it introduces or weaknesses it keeps.

## Findings

### 1. Weakened action-method existence check (regression)
- **Location:** `dispatch()`, the `is_callable([$controllerObj, $actionMethod])` branch and the `$isProcessing ||` short-circuit.
- **OWASP:** A04 Insecure Design / A01 Broken Access Control
- **Problem:**
  - The old code had a comment that `is_callable()` is always true on Smarty 4 because of `__call`, so it also required `method_exists()`. The new code drops `method_exists()` and relies on `is_callable()` alone.
  - The new `NotFoundHttpException` for a missing action is therefore effectively dead code. Any attacker-chosen `action` string reaches `$controllerObj->{$action}_action(...)`. Unknown names fall into Smarty's magic `__call`, and protected methods ending in `_action` are reachable from `Controller` scope.
  - The old code also stripped the action name with `preg_replace('/[^A-Za-z0-9_]/', '', ...)`. That sanitisation is gone. `$action` is now an arbitrary string used as a dynamic method name and stored in `_current_action`, which is later used by `_link()` and templates.
  - In processing mode (`$isProcessing`) the action is invoked with no existence check at all.
- **Severity:** Medium. The `_action` suffix limits the blast radius, but this is a lost defence-in-depth control.
- **Fix:** Restore `method_exists()` (or `ReflectionMethod` with `isPublic()`), and restrict `$action` to `^[A-Za-z0-9_]+$`.

### 2. ACL enforced for only two of ten controllers; sub-controllers reachable directly (pre-existing, carried forward)
- **Location:** `CONTROLLER_ACL_MAP`, `checkControllerAcl()`, `dispatch()`. Related: `C_PracticeSettings::*_action`.
- **OWASP:** A01 Broken Access Control
- **Problem:**
  - Only `practice_settings` and `prescription` are in the ACL map. `pharmacy`, `insurance_company`, `insurance_numbers`, `x12_partner`, `hl7`, `document_category`, `document` and `patient_finder` get no authorization check in the dispatcher.
  - `C_PracticeSettings` enforces `admin/practice` and then dispatches to `pharmacy`, `insurance_company`, `x12_partner` and `hl7`. Those same controllers are whitelisted and reachable directly via `controller.php?controller=x12_partner&action=...`.
  - Unless each controller enforces its own ACL (not visible in this diff), a low-privileged logged-in user can reach admin-level functions and PHI-bearing documents while skipping the `practice_settings` check.
- **Severity:** High if the individual controllers do not self-check. Please verify each one. Medium otherwise.
- **Fix:** Make the ACL map mandatory for every entry in `VALID_CONTROLLERS`, and fail closed if a controller has no mapping. Map the sub-controllers to `admin/practice` and documents to the appropriate `patients/docs` ACL.

### 3. State-changing "process" mode can be triggered via GET, with no CSRF protection (pre-existing)
- **Location:** `dispatch()`, the `isset($params['process'])` block that sets `$_POST['process'] = "true"`. Also `act()`, which forwards the extra `process` key.
- **OWASP:** A01 / A04 Insecure Design (CSRF)
- **Problem:**
  - A `?process=anything` query parameter is converted into a synthetic POST flag, which runs the `*_action_process` handlers (writes and deletes). These can be triggered by a plain link or image tag.
  - There is no CSRF token check in the dispatcher.
  - The process method does not need to exist for the write path to run, because `$isProcessing` forces the action call.
- **Severity:** Medium
- **Fix:** Require a real POST with a verified CSRF token (`CsrfUtils::verifyCsrfToken`) before any process handler runs, and never derive POST state from `$_GET`.

### 4. Unvalidated, attacker-controlled arguments spread positionally into action methods
- **Location:** `dispatch()`, the `$args` construction and `$callMethod(...array_values($args))`. Also `act()`, the remaining-params loop.
- **OWASP:** A04 Insecure Design
- **Problem:**
  - Every extra query parameter is passed positionally to the action. Parameter order and count therefore influence which argument lands in which parameter, and an attacker can inject extra or reordered arguments.
  - Array values (`id[]=x`) are passed through unchanged, causing type confusion or `TypeError` in handlers.
  - The old code at least sanitised the key names; the new code does not. The rename of `action` to `sub_action` in `act()` also changes the argument semantics.
- **Severity:** Low to Medium
- **Fix:** Dispatch with named arguments or reflection against a declared signature, and validate and cast types.

### 5. Reflected user input and internal details in exception messages
- **Location:** `NotFoundHttpException("Action '$action' does not exist on controller: $className")` and `"Unable to load controller: $className"`.
- **OWASP:** A03 Injection (XSS) / A05 Security Misconfiguration
- **Problem:**
  - The raw `$action` value is embedded in an exception message. If the exception handler renders messages as HTML without escaping, this is reflected XSS.
  - Class names and file-load failures are also disclosed.
  - Unknown actions that fall through to Smarty's `__call` may emit Smarty exceptions that leak further internals.
- **Severity:** Low (XSS depends on how the handler renders)
- **Fix:** Use generic messages, log the details server-side, and escape on output.

### 6. Logging gap
- **Location:** the `AccessDeniedHelper::denyWithTemplate` path and the new exceptions.
- **OWASP:** A09 Security Logging and Monitoring Failures
- **Problem:** Invalid controller or action probing and process-mode invocations are not logged as security events.
- **Severity:** Low

## Checked and fine
- **Path traversal / LFI:** the controller file path is built only from the whitelist constants.
- **`C_PracticeSettings` `FORM_ACTION`:** it uses `attr()` on `QUERY_STRING`, so the output is escaped.
- **`new $className()`:** the class name comes only from the constant map.

## Summary
Findings 1 and 2 are the ones to address before merging. Restore the `method_exists` check and action sanitisation, and verify or add ACLs for the other whitelisted controllers.
