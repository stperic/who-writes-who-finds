Known vulnerability:
CVE-2026-33321 (server-side request forgery, OWASP A10), file interface/forms/eye_mag/report.php.
This change adds the eye exam report, which echoes stored, user-supplied values without
escaping into HTML and into CSS url() contexts (for example background: <?php echo $background; ?>
and free-text fields such as HPI, motility, visual field, Rx type and plan/order details). The
patient report page renders forms' report.php output server-side into a PDF with an HTML-to-PDF
renderer, which fetches URLs in the markup. Injected URLs are therefore fetched by the server:
out-of-band server-side request forgery. The root cause is the missing output escaping; the
same flaw also allows HTML injection in the browser view.

# Code Review Issues

## Critical Issues

### 1. **SQL Injection Vulnerability** - HIGH SEVERITY
**Location:** Line 1533 (and similar patterns throughout)
```php
$sql = "SELECT * from documents where documents.url like '%".$filename."'";
$doc = sqlQuery($sql);
```
**Problem:** User-controlled data (`$filename`) is concatenated directly into SQL query without parameterized statements. This is vulnerable to SQL injection attacks.
**Fix:** Use parameterized queries:
```php
$sql = "SELECT * from documents where documents.url like ?";
$doc = sqlQuery($sql, array('%'.$filename.'%'));
```

### 2. **SQL Injection in Multiple Locations** - HIGH SEVERITY
**Location:** Lines 69-72, 1375
```php
if ($_REQUEST['CHOICE']) $choice = $_REQUEST['choice'];  // case mismatch, security issue
if ($_REQUEST['ptid']) $pid = $_REQUEST['ptid'];
if ($_REQUEST['encid']) $encounter=$_REQUEST['encid'];
```
**Problem:** Request parameters are used directly in queries without validation or sanitization. Line 69 shows a case mismatch (`CHOICE` vs `choice`).
**Fix:** Validate and sanitize all input:
```php
$pid = isset($_REQUEST['ptid']) ? (int)$_REQUEST['ptid'] : null;
$encounter = isset($_REQUEST['encid']) ? (int)$_REQUEST['encid'] : null;
```

### 3. **Unsafe File Path Handling** - HIGH SEVERITY
**Location:** Lines 336-340, 1545-1556
```php
$from_file = $GLOBALS["fileroot"] . "/sites/" . $_SESSION['site_id'] .
'/documents/' . $from_pathname . '/' . $from_filename;
```
**Problem:** `$from_pathname` and `$from_filename` are not validated and could contain path traversal sequences (`../`).
**Fix:** Validate paths to prevent directory traversal attacks.

### 4. **Missing CSRF Protection** - MEDIUM SEVERITY
**Location:** Line 62 onwards (form processing)
**Problem:** No CSRF token validation visible in the report display function.

### 5. **Use of `extract()` with Untrusted Data** - HIGH SEVERITY
**Location:** Lines 92, 245
```php
@extract($objQuery);
@extract($encounter_data);
```
**Problem:** `extract()` on database results can overwrite variables. Using `@` suppresses error handling. Combined with variable variables like `$$LOCATION` (line 75), this is dangerous.
**Fix:** Use explicit variable assignment or array access.
