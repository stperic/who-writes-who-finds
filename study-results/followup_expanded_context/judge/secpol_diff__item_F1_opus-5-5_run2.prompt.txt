# Security Review: `library/classes/Controller.class.php` routing refactor

The whitelist of controller names is an improvement. It closes the old pattern of building an include path from user input. However, the refactor drops two safeguards on the **action** parameter. It also keeps, and formalizes, several older access-control and CSRF weaknesses.

---

## 1. Unvalidated `action` reaches Smarty's magic `__call()` (removed `method_exists()` check and removed input sanitization)

**Location:** `dispatch()`. The relevant lines are:
- `$action = is_string($params['action'] ?? null) ? $params['action'] : 'default';`
- `if ($isProcessing && is_callable([$controllerObj, $processMethod]))`
- `if ($isProcessing || is_callable([$controllerObj, $actionMethod]))`

**OWASP:** A01 Broken Access Control / A04 Insecure Design

**Problem:**
- **Sanitization removed.** The old code ran the action through `preg_replace("/[^A-Za-z0-9_]/", "", ...)`. The new code uses the raw query-string value to build the method name.
- **`method_exists()` removed.** The deleted comment explained why it was needed: *"Smarty 4 invokes a `__call` function … thus `is_callable()` is always true. so need to do both the `is_callable` and a `method_exists()` check."* `Controller extends Smarty`, so `is_callable()` now returns `true` for any name. The `else` branch that throws `NotFoundHttpException` is effectively unreachable.
- **Every action is dispatched.** Any `{anything}_action` name goes either to a real method or to Smarty's `__call` → `ext->_callExternalMethod()`. That handler has its own dynamic behavior: `set*`/`get*` property accessors and dynamic `Smarty_Internal_Method_*` class resolution, both driven by the attacker-supplied name.
- **The process path calls `$actionMethod` with no check at all.** When `process=true`, the second branch runs because of `$isProcessing ||`.
- **Non-public methods may become routable.** `is_callable()` and the call itself run inside `Controller`'s scope. PHP therefore allows calls to `protected` methods declared in subclasses and `private`/`protected` methods declared in `Controller`. Any non-public helper whose name ends in `_action` can now be invoked from a URL.

**Severity:** Medium. It could be higher depending on which `*_action` methods and Smarty extension handlers are reachable.

**Fix:**
- Restore strict validation, e.g. `preg_match('/^[A-Za-z0-9_]+$/', $action)`, or use a per-controller whitelist of actions.
- Require the method to exist and be public, using `method_exists()` together with `(new ReflectionMethod($obj, $m))->isPublic()`.
- Apply the same check before the unconditional call in the processing path.

## 2. Reflected user input in exception messages (possible XSS / log injection)

**Location:** `throw new NotFoundHttpException("Action '$action' does not exist on controller: $className");`

**OWASP:** A03 Injection (XSS)

**Problem:**
- The old `echo` printed only the sanitized `$c_action`. The new message embeds the raw `action` value.
- If the global exception handler renders the message as HTML without escaping (common in dev/debug mode or custom error pages), this is reflected XSS. A payload like `?controller=document&action=<script>…</script>` would work.
- The raw value will also land in logs unescaped (A09 log injection / forging).

Note that, given issue #1, this branch is currently hard to reach. Once #1 is fixed it becomes reachable, so the two fixes should go together.

**Severity:** Low–Medium. It depends on how exceptions are rendered.

**Fix:**
- Do not echo raw input in exception messages, or validate the action first (fix #1).
- Make sure the exception handler escapes messages (`text()`/`attr()`).

---

## 3. (Pre-existing, carried forward) ACL enforced only for two top-level controllers; sub-controllers reachable directly

**Location:** `CONTROLLER_ACL_MAP` and `checkControllerAcl()`

**OWASP:** A01 Broken Access Control

**Problem:**
- Only `practice_settings` (admin/practice) and `prescription` (patients/rx) are checked.
- Several administrative controllers are normally reached through Practice Settings: `pharmacy`, `insurance_company`, `insurance_numbers`, `x12_partner`, `document_category`, and `hl7`. The comment in `act()` even mentions `practice_settings->pharmacy->list`.
- All of these are in `VALID_CONTROLLERS` and can be targeted directly. Example: `controller.php?x12_partner&edit&process=true`, or `dispatch(['controller' => 'pharmacy', ...])`.
- None of these require admin/practice ACL here. Any authenticated user could view or modify pharmacies, insurance companies, X12 partners, or document categories unless each controller checks ACL itself.
- `document` and `patient_finder` have no central ACL either. Patient document access by `patient_id`/`doc_id` must be authorized inside `C_Document`, or this is an IDOR exposing PHI.

The old code had the same gap. The new whitelist plus a separate, incomplete ACL map makes the gap explicit and easy to fix.

**Severity:** High (PHI and administrative data exposure or modification).

**Fix:**
- Make ACL mandatory for every whitelisted controller. For example, merge the two maps so each entry must declare its ACL and a missing entry denies access.
- At minimum, map all practice-settings sub-controllers to `admin/practice`.
- Map documents to `patients/docs` and add per-patient authorization checks.

## 4. (Pre-existing, preserved) GET `process` flag promoted to POST → state-changing actions via GET / CSRF

**Location:** `dispatch()`, where `if (isset($params['process'])) { ... $_POST['process'] = "true"; }`

**OWASP:** A01 Broken Access Control (CSRF) / A04 Insecure Design

**Problem:**
- Putting `process` in the query string causes the `*_action_process` handlers to run. These are the create/update/delete handlers.
- This turns state-changing operations into GET requests. Any `<img src="…controller.php?pharmacy&edit&process=true&…">` on an attacker page can trigger them in a logged-in clinician's session.
- The router does no CSRF token verification. Any `_action_process` method that does not call `CsrfUtils::verifyCsrfToken()` itself is exploitable.
- The new `dispatch()` API keeps this behavior. It also mutates superglobals (`$_GET`, `$_POST`) from a method that is documented to take arbitrary `$params`.

**Severity:** Medium.

**Fix:**
- Remove the GET-to-POST promotion.
- Require a real POST for processing.
- Verify the CSRF token centrally in `dispatch()` before calling any `*_process` method.

---

## 5. Query parameters can override routing in `act()` (low)

**Location:** `act()`, where `$params[$key === 'action' ? 'sub_action' : $key] = $value;`

**OWASP:** A04 Insecure Design

**Problem:**
- `action` is renamed, but `controller` is not. A request like `?pharmacy&list&controller=document` silently changes the dispatched controller away from the positional one.
- The ACL is evaluated on the final controller, so this is not a direct bypass today. Still, routing becomes ambiguous, and it will become one if any upstream code (logging, auditing, or ACL keyed on the first key) assumes the positional controller.

**Severity:** Low.

**Fix:** Skip or reject `controller` (and `process`) in the remaining-parameter loop.

---

## 6. Arbitrary positional argument injection (pre-existing, slightly broadened)

**Location:** `dispatch()`, specifically `$controllerObj->$method(...array_values($args))`

**OWASP:** A04 Insecure Design / A03 Injection (depending on the callee)

**Problem:**
- All non-reserved query parameters are passed positionally, in whatever order the attacker sends them. Values can be arrays, e.g. `foo[]=1`.
- Previously, argument key names were sanitized. Now any key passes through, including `sub_action`.
- Attackers control the count, order, and type of arguments to action methods. That can break assumptions such as a parameter being a numeric ID, and may enable type confusion or injection in methods that do not validate their inputs.

**Severity:** Low–Medium. It depends on the downstream methods.

**Fix:**
- Bind arguments by name, e.g. via `ReflectionMethod::getParameters()`.
- Validate types (cast IDs to int) and reject array values where scalars are expected.
