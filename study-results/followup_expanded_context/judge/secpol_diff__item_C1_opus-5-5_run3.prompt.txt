# Security Review: `C_Document::retrieve_action()` — `$disable_exit` change

## Summary

The change adds a `$disable_exit` flag so `retrieve_action()` returns document content to the caller instead of streaming it. This turns a request-handling endpoint into a general "read any document" function. Because the function does no authorization of its own, every new caller inherits that gap. The new return paths also skip the download audit log and silently ignore the encryption request.

Several issues below are in pre-existing code that the change relies on. Where that code is outside the diff, the finding is based on the visible context and the upstream OpenEMR implementation, so confirm it against your tree.

---

## Findings

### 1. No authorization or patient-ownership check before reading the document
- **Location:** `retrieve_action()`. The document is loaded from `$document_id`, and the new `return` statements (lines ~433, ~516) hand back its content.
- **OWASP:** A01:2021 – Broken Access Control
- **Severity:** **High** (PHI disclosure)
- **Problem:**
  - The document is fetched by ID alone. The function never checks the following:
    - that the document belongs to `$patient_id`;
    - that the user has the document-category ACL (e.g. `$d->can_access()` / `acl_check('patients','docs')`);
    - that the document is not soft-deleted.
  - This is an IDOR: incrementing `document_id` retrieves other patients' records.
  - The new `$disable_exit` path makes this worse. Any internal caller (report generation, CCD/CCDA export, portal, fax/email features) can pull content for a user-influenced ID without any gate. Those callers will likely assume `retrieve_action` already did the check.
- **Fix:**
  - Before reading any content, validate all of the following:
    - `$d->get_foreign_id() == $patient_id`;
    - the per-category ACL;
    - the deleted flag.
  - Return an error, not content, if any check fails.
  - Keep the check in this function, not in the callers.

### 2. New return paths bypass the document access audit log
- **Location:** The three new `if ($disable_exit == true) return ...` blocks.
- **OWASP:** A09:2021 – Security Logging and Monitoring Failures
- **Severity:** **Medium** (HIPAA audit-trail requirement for PHI access)
- **Problem:**
  - `document_upload_download_log()` is called only in the CouchDB failure path shown here and in the existing streaming/encryption flow.
  - Content returned through `$disable_exit` is never logged.
  - Bulk export or reporting features built on this flag will read patient documents with no audit record.
- **Fix:** Log every successful retrieval (user, patient, document ID, purpose) before returning, regardless of how the content is delivered.

### 3. Encryption request silently ignored on the new path
- **Location:** Lines ~513–517. The file is read and returned before the `if ($doEncryption)` branch.
- **OWASP:** A04:2021 – Insecure Design
- **Severity:** **Medium**
- **Problem:**
  - `$encrypted` and `$passphrase` come from `$_POST`. With `$disable_exit`, the plaintext is returned no matter what encryption was requested.
  - The CouchDB branch behaves the same way.
  - A caller that expects the encrypted-download behaviour (e.g. sending a document off-system) will send plaintext PHI with no error.
- **Fix:** Either apply the same encryption logic before returning, or fail explicitly when `$disable_exit && $doEncryption`. Better still, pass the encryption options as explicit parameters instead of reading `$_POST` inside a function that is now used as a library call.

### 4. Weak or legacy cryptography in `encrypt()` (pre-existing, relied upon)
- **Location:** `$this->encrypt($filetext, $passphrase)` and the `encrypt()` method.
- **OWASP:** A02:2021 – Cryptographic Failures
- **Severity:** **Medium–High**
- **Problem:**
  - Upstream, this method uses `mcrypt` with 3DES in ECB mode. The passphrase is used directly as the key, with no KDF, salt, IV, or authentication.
  - ECB leaks patterns. 3DES is deprecated. `mcrypt` was removed in PHP 7.2.
- **Fix:**
  - Use libsodium (`sodium_crypto_secretbox`) or OpenSSL AES-256-GCM.
  - Derive the key with `sodium_crypto_pwhash` / PBKDF2 using a random salt.
  - Generate a random nonce per file.

### 5. Plaintext/ciphertext written to a predictable temp path (pre-existing)
- **Location:** The `$tmpfilename = "/encrypted_".$d->get_url_file();` block in `temporary_files_dir`.
- **OWASP:** A05:2021 – Security Misconfiguration / A01
- **Severity:** **Low–Medium**
- **Problem:**
  - The filename is predictable and built from the stored filename.
  - Concurrent requests for the same document collide.
  - If the file is not reliably unlinked, documents accumulate in a shared temp directory that may be readable by other processes or web-exposed.
- **Fix:**
  - Use `tempnam()` or stream from memory.
  - Always `unlink` in a `finally`-style path.
  - Make sure the temp directory is outside the web root and has restrictive permissions.

### 6. Filesystem path built from stored document URL (pre-existing, relied upon)
- **Location:** The `$url` used in `fopen($url,"r")` / `filesize($url)` and the converted-file path `$GLOBALS['OE_SITE_DIR'] . '/documents/' . $from_pathname . '/' . $convertedFile`.
- **OWASP:** A01:2021 (path traversal) / A03:2021
- **Severity:** **Medium** (depends on how `url` can be set)
- **Problem:**
  - The path comes from the document's DB `url` field.
  - If that field can be influenced (import, API, or document move/rename features), `../` or absolute paths could make the function read arbitrary server files.
  - The new path then returns those bytes to the caller.
  - Upstream rebuilds the path from `basename` plus the last directory segment, which limits this. That only helps if both segments are validated.
- **Fix:**
  - Resolve the final path with `realpath()`.
  - Verify it starts with `realpath($GLOBALS['OE_SITE_DIR'].'/documents/')` before opening it.

### 7. Stored XSS through inline serving of uploaded content (pre-existing, relied upon)
- **Location:** The streaming branch after the new checks, where `Content-Type` is set from the stored mimetype. When `$as_file` is false, `Content-Disposition` is `inline`.
- **OWASP:** A03:2021 – Injection (XSS)
- **Severity:** **Medium–High**
- **Problem:**
  - An uploaded `.html`/`.svg` file (or one whose mimetype was spoofed on upload) is rendered inline from the application's origin.
  - Its scripts then run in a clinician's authenticated session.
- **Fix:**
  - Force `Content-Disposition: attachment` for anything that is not an allow-listed safe type.
  - Send `X-Content-Type-Options: nosniff` and a restrictive `Content-Security-Policy` (e.g. `sandbox`).
  - Ideally, serve documents from a separate origin.

### 8. Unchecked `fopen` / unbounded read / leaked handle (introduced)
- **Location:** New lines `$f = fopen($url,"r"); $filetext = fread($f, filesize($url));`
- **OWASP:** A04:2021 – Insecure Design (robustness / DoS)
- **Severity:** **Low**
- **Problem:**
  - `fopen` failure is not checked, so `fread(false, ...)` produces warnings. If `display_errors` is on, those warnings can leak filesystem paths.
  - The whole file is now read into memory for every non-converted request. Before this change, that happened only when encrypting. Large documents can exhaust memory, which is a DoS risk.
  - The handle is never closed on the early-return path.
- **Fix:**
  - Check the return value.
  - Only buffer when `$disable_exit` or encryption needs it; otherwise stream with `fpassthru`/`readfile`.
  - Call `fclose($f)`.

### 9. Converted-file path returns nothing (functional, low security impact)
- **Location:** Line ~554, `if ($disable_exit == true) { return ; }`
- **Severity:** **Informational**
- **Problem:** Callers get `null` for converted documents. They may handle this by falling back to some other retrieval method that also lacks access checks, or by silently omitting records from an export.
- **Fix:** Return the converted file's content, after the same access checks and audit logging as the other paths.

---

## Recommendation

**Do not merge as-is.** At minimum, before this function is exposed as a content-returning API:
- add the patient/ACL authorization check (Finding 1);
- add audit logging on all return paths (Finding 2);
- fail closed or honor the encryption request (Finding 3).

Track Findings 4–7 as pre-existing issues this change depends on. Consider splitting the change into two pieces:
- a separate `getDocumentContent($document_id, $patient_id)` method with built-in authorization and logging;
- `retrieve_action` as a thin HTTP wrapper around it, instead of overloading the controller action with a flag.
