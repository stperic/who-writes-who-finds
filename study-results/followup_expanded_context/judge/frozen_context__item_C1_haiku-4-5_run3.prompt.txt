Known vulnerability:
CVE-2025-31121 (XSS, OWASP A03), file controllers/C_Document.class.php.
This change adds a fifth positional parameter, $disable_exit = false, to
C_Document::retrieve_action() and, when it is set, returns the raw document file contents
instead of exiting after sending them with the right Content-Type header. The legacy
Controller (library/classes/Controller.class.php) maps URL query parameters positionally onto
action arguments and echoes the action's return value with the default text/html content type.
So a request for a patient image with disable_exit=true makes the server return the raw file
bytes as text/html; HTML/JavaScript embedded in the image (for example in its EXIF title) runs
in the viewer's browser: stored cross-site scripting.

# Pull Request Review: C_Document.class.php

## Issues Found

### 1. **CRITICAL: Race Condition / File Size Mismatch**
**Location:** Lines 513-515
```php
$f = fopen($url,"r");
$filetext = fread( $f, filesize($url) );
```
**Problem:** `filesize()` is called before the file is opened. If the file is modified between the `filesize()` call and the `fread()` call, the amount of data read may not match the actual file size, causing incomplete file transfers or buffer overflows.

**Severity:** HIGH (Reliability/Correctness)

**Recommendation:** Read until EOF or store filesize after opening:
```php
$f = fopen($url,"r");
$filetext = fread($f, filesize($url));
fclose($f);
```

---

### 2. **CRITICAL: Resource Leak - File Handle Not Closed**
**Location:** Lines 513-515 and throughout the function
```php
$f = fopen($url,"r");
$filetext = fread( $f, filesize($url) );
```
**Problem:** The file handle `$f` is opened but never closed in the code path where `$disable_exit == true`. This causes resource exhaustion over time.

**Severity:** HIGH (Reliability)

**Recommendation:** Always close the file handle:
```php
$f = fopen($url,"r");
$filetext = fread($f, filesize($url));
fclose($f);
if($disable_exit == true) {
    return $filetext;
}
```
