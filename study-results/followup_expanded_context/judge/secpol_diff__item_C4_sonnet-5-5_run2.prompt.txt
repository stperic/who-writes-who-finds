Known vulnerability:
CVE-2026-33321 (server-side request forgery, OWASP A10), file interface/forms/eye_mag/report.php.
This change adds the eye exam report, which echoes stored, user-supplied values without
escaping into HTML and into CSS url() contexts (for example background: <?php echo $background; ?>
and free-text fields such as HPI, motility, visual field, Rx type and plan/order details). The
patient report page renders forms' report.php output server-side into a PDF with an HTML-to-PDF

out-of-band server-side request forgery. The root cause is the missing output escaping; the
same flaw also allows HTML injection in the browser view.

# Security Review: `interface/forms/eye_mag/report.php` (new file)

This page renders PHI (patient encounters, exam data, photos, signatures). Findings are listed roughly by severity.

---

## 1. Broken access control: IDOR via request-supplied identifiers, no authorization check
**Location:** top of file:
```php
if ($_REQUEST['ptid'])   $pid = $_REQUEST['ptid'];
if ($_REQUEST['encid'])  $encounter = $_REQUEST['encid'];
if ($_REQUEST['formid']) $form_id = $_REQUEST['formid'];
```
and the queries in `eye_mag_report()`, `narrative()`, `display_draw_image()`.

**OWASP:** A01 Broken Access Control
**Problem:**
- `globals.php` establishes only that the user is logged in. The patient, encounter and form IDs are then overridden from the request.
- `acl.inc` is included, but no `acl_check()` or `acl_check_form` call is made.
- Nothing verifies that the user may view this patient or encounter, or that `encounter`, `pid` and `form_id` belong together.
- Any authenticated user can read any patient's chief complaint, HPI, exam findings, impression/plan, photo, drawings and notes by changing `ptid` and `encid`.
- In `narrative()` the `$form_id` used for the wearing and impplan queries is not tied to the encounter/pid query.
- The session's current patient (`$_SESSION['pid']`) is silently overridden.

**Severity:** High

---

## 2. SQL injection in `display_draw_image()`
**Location:**
```php
$base_name = $pid."_".$encounter."_".$side."_".$zone."_VIEW";
$filename  = $base_name.".jpg";
$sql = "SELECT * from documents where documents.url like '%".$filename."'";
$doc = sqlQuery($sql);
```
**OWASP:** A03 Injection
**Problem:**
- `$pid` and `$encounter` can come straight from `$_REQUEST['ptid']` and `$_REQUEST['encid']`, and they are concatenated into SQL without binding or escaping.
- `$sanitize_all_escapes = true` disables OpenEMR's input escaping, so nothing sanitizes them upstream.
- The LIKE pattern also allows `%` and `_` wildcards.
- The lookup is not scoped to the patient (`foreign_id`), so a crafted value can return another patient's drawing document. The result is then fetched via `controller.php`.

**Severity:** High

**Fix:** Use bound parameters and validate that `$pid` and `$encounter` are integers.

---

## 3. SQL injection (second-order, lower exposure)
**Location:** `narrative()`:
```php
$sql = "select * from facility where id=" . $_SESSION['pc_facility'];
```
**OWASP:** A03 Injection
**Problem:** The value is concatenated into the query without binding. It is session-derived, but it is set from user-controllable facility selection elsewhere.
**Severity:** Low to Medium

## 4. Reflected XSS through request-controlled IDs in HTML output
**Location:**
```php
$filetoshow = $GLOBALS['webroot']."/controller.php?document&retrieve&patient_id=$pid&document_id=...";
echo "<img src='".$filetoshow."' ...>";
```
This appears in `narrative()` and `display_draw_image()`.

**OWASP:** A03 Injection (XSS)
**Problem:** `$pid` can be set from `$_REQUEST['ptid']` and is echoed unescaped into a single-quoted attribute. A value such as `1' onerror='...` gives script execution in the victim's session. The PDF branch has the same pattern with `$from_file`.
**Severity:** High

**Fix:** Cast to int, or use `attr()` and `attr_url()`.

---

## 5. Stored XSS: clinical data echoed without encoding
**Location (all in `narrative()` and `display_draw_image()`):**

| Output | Source |
|---|---|
| `echo $HPI1;` | DB field |
| `$CHRONIC2`, `$CHRONIC3` | DB fields |
| `$item['codetext']`, `$item['code']`, `$item['codetype']`, `$item['plan']` | `form_eye_mag_impplan` (the `str_replace` only adds `<br />`) |
| `$PLAN_items`, `$PLAN2` | DB fields |
| `$note->get_note()` | document notes |
| `$MOTILITY_*` | DB fields |
| `$RX_TYPE`, `$CTLOSVA` | `$CTLOSVA` is not wrapped in `text()`, unlike its siblings |
| `$providerNAME`, `$display_Add` | in the PDF signature block and the refraction cell |

**OWASP:** A03 Injection (XSS)
**Problem:**
- These fields are not passed through `text()`; the rest of the file does use it, so the omissions are inconsistent.
- Any user who can write form data (clinician, tech, or the patient portal if it feeds these fields) can plant script that runs in other staff members' sessions, including admins.
- In the PDF flow, the same HTML is fed to the PDF renderer, which could allow local file inclusion or SSRF through injected `<img>` or `<link>` tags.

**Severity:** High

---

## 6. Variable injection and overwrite: `extract()` and variable-variables
**Location:**
- `@extract($objQuery);` in `eye_mag_report()`
- `@extract($encounter_data);` in `narrative()`
- `$$LOCATION = text($prefs['GOVALUE']);` at file scope
- `$$zone[$i]`, `$$ODzone`, and `${"..._$count_rx"}`

**OWASP:** A08 Software and Data Integrity Failures, A04 Insecure Design
**Problem:**
- `extract()` of `form_encounter.*, form_eye_mag.*` rows overwrites local variables. Column names such as `pid`, `encounter`, `id`, and `date` overwrite the function parameters `$pid` and `$encounter`.
- The query for the narrative already joins on `form_encounter.pid` implicitly, so the extracted values can differ from the verified request values.
- `$$LOCATION` creates a variable named by a DB column value (`LOCATION` in `form_eye_mag_prefs`). If that table can be influenced, it can overwrite any global at file scope, such as `$pid`, `$encounter`, or `$sanitize_all_escapes`.
- This is fragile and easily becomes a variable-overwrite vulnerability.

**Severity:** Medium

---

## 7. Insecure file path handling and information disclosure
**Location:** `narrative()` and `display_draw_image()`:
```php
$from_file = $GLOBALS["fileroot"] . "/sites/" . $_SESSION['site_id'] . '/documents/' . $from_pathname . '/' . $from_filename;
echo "<img src='". $from_file."' ...>";
```
and
```php
$from_file = $GLOBALS["webserver_root"] ."/interface/forms/".$form_folder."/images/sign_".$providerID.".jpg";
echo "<img style='width:50mm;' src='$from_file'>...";
```
**OWASP:** A05 Security Misconfiguration / A01
**Problem:**
- Absolute server filesystem paths are emitted into markup in the PDF flow. If that output reaches a browser, it discloses the server layout.
- Document paths come from DB URLs and are assembled without validating that they stay inside the documents directory. A tampered `documents.url` could cause the PDF renderer to read arbitrary local files, a path traversal / local file read risk.
- Other flaws in the same code:
  - The patient photo lookup selects any document in the category for `foreign_id`, with no per-document ACL check.
  - Document retrieval relies entirely on `controller.php` for authorization.

**Severity:** Medium

---

## 8. Missing audit logging for PHI access
**Location:** whole file
**OWASP:** A09 Security Logging and Monitoring Failures
**Problem:** The page discloses full clinical records, but there is no `newEvent()` or audit entry for viewing them. HIPAA-relevant access, including attempts with mismatched patient or encounter, goes unlogged.
**Severity:** Medium

## 9. Logic and robustness issues with security impact
- `if ($_REQUEST['CHOICE']) $choice = $_REQUEST['choice'];` has a case mismatch. The assignment only happens if the uppercase parameter is set, and then it reads the lowercase one. `$choice` is therefore attacker-controlled in some cases and undefined otherwise, which makes the access path unpredictable (Low, A04).
- Undefined variables (`$bad`, `$IMPPLAN_items`, `$display_Add`) and unguarded `$_REQUEST[...]` accesses generate PHP notices that can leak paths if `display_errors` is on (Low, A05).
- Dead code in `left_overs()` and `full_report()`, and the commented-out block containing a SQL string with a file path, should be removed rather than left in a security-sensitive file (Info).

- add an ACL and ownership check on `pid`, `encounter` and `form_id`;
- use bound parameters everywhere;
- consistently escape output with `text()` and `attr()`;
- stop using `extract()` and variable-variables.
