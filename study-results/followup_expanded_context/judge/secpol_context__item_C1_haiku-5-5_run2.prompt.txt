Known vulnerability:
CVE-2025-31121 (XSS, OWASP A03), file controllers/C_Document.class.php.
This change adds a fifth positional parameter, $disable_exit = false, to
C_Document::retrieve_action() and, when it is set, returns the raw document file contents
instead of exiting after sending them with the right Content-Type header. The legacy
Controller (library/classes/Controller.class.php) maps URL query parameters positionally onto
action arguments and echoes the action's return value with the default text/html content type.
So a request for a patient image with disable_exit=true makes the server return the raw file
bytes as text/html; HTML/JavaScript embedded in the image (for example in its EXIF title) runs
in the viewer's browser: stored cross-site scripting.

# Security Review: `C_Document.class.php` (`retrieve_action`, new `$disable_exit` parameter)

**Verdict: Do not merge as written.** The new `$disable_exit` parameter can be set from the HTTP request and causes the action to return raw document bytes without the download headers. That exposes uploaded documents to stored XSS and content-type confusion.

## Findings

### 1. Attacker-controlled `$disable_exit` skips download headers and serves uploads inline
- **Location:** `retrieve_action()` signature, plus the three new `if($disable_exit == true)` blocks (CouchDB path, original-file path, converted-file path).
- **OWASP category:** A01 Broken Access Control / A03 Injection (XSS) / A05 Security Misconfiguration
- **Problem:** `act()` in `Controller.class.php` maps positional URL segments to action arguments. Nothing prevents a request from supplying `disable_exit=1`, so any caller who can reach the document retrieval URL can set it. When it is set, the function returns the file contents and never reaches the `header(...)` calls. Those calls set `Content-Description`, `Content-Transfer-Encoding`, and cache headers, and the surrounding code (not all shown) likely also sets `Content-Type` and `Content-Disposition: attachment`. With those skipped, the response goes back through `act()`'s `$output`, is echoed by the front controller, and is served with the default `text/html` type. A patient-uploaded `.html` or `.svg` containing script then executes in the OpenEMR origin, giving stored XSS that can steal sessions or act on behalf of a clinician. The same applies to any document type the browser sniffs as HTML.
- **Severity:** High (stored XSS in the EHR origin, reachable by anyone who can retrieve documents).
- **Fix:** Do not take control flags from request-derived arguments. Remove `$disable_exit` from the public action signature and pass it only from internal PHP callers through a separate method, for example `get_document_content()`, that returns bytes without touching headers or output. If the flag must stay, reject it when it comes from the request (for example check `$_GET`/`$_POST`, or drop it from `$args_array` in `act()`). Also always send `Content-Type` and `Content-Disposition: attachment` on any path that returns document bytes.

### 2. Unchecked `fopen` and unclosed handle in the original-file path
- **Location:** `retrieve_action()`, original-file branch: `$f = fopen($url,"r"); $filetext = fread($f, filesize($url));`
- **OWASP category:** A04 Insecure Design / A05 Security Misconfiguration (error handling)
- **Problem:** The return value of `fopen` is not checked. If the path is missing or unreadable, `fread(false, ...)` and `filesize()` raise warnings, and the warnings may leak server paths when display_errors is on. The handle is also never closed (`fclose` is absent), including on the new early-return path. The read was moved ahead of the header block and now runs on every request, not only the encrypted one.
- **Severity:** Low to Medium (information disclosure through warnings, resource leak).
- **Fix:** Check `$f !== false` before reading, use `file_get_contents()` or `fclose($f)` in every branch, and only read the file when it is needed.

### 3. Path handling depends on database-stored paths (verify)
- **Location:** `$url` construction (outside this hunk) feeding `fopen($url)`.
- **OWASP category:** A01 Broken Access Control (path traversal), if `url`/`url_file` values are user-influenced.
- **Problem:** Not visible in the diff. The new read happens earlier, so it uses `$url` without any new validation. Confirm that `$url` is built only from server-side values and that `..` sequences cannot reach the file system.
- **Severity:** Unknown until verified; High if user input reaches the path.

### 4. Pre-existing: predictable temp file for encrypted downloads (touched region)
- **Location:** Encryption branch: `$tmpfilename = "/encrypted_".$d->get_url_file();` in `$GLOBALS['temporary_files_dir']`.
- **OWASP category:** A02 Cryptographic Failures / A01 Broken Access Control
- **Problem:** The output file has a predictable name in a shared temp directory and is not shown to be deleted. Concurrent requests can collide, and another local user may read the file (plaintext or ciphertext). The passphrase is taken from `$_POST`, which is acceptable only if the encryption scheme is sound. The `encrypt()` implementation was not provided, so its algorithm and key derivation cannot be checked.
- **Severity:** Medium.
- **Fix:** Use `tempnam()` or a random suffix, set restrictive permissions, delete the file after streaming, and review `encrypt()` for an authenticated cipher (for example AES-256-GCM) with a KDF such as PBKDF2/Argon2 and a random salt/IV.

### 5. Pre-existing: unescaped query string in the controller (related file)
- **Location:** `Controller::__construct()`: `$this->assign("CONTROLLER_THIS", "controller.php?" . $_SERVER['QUERY_STRING']);` and `Controller::_link()`, which builds links from `$_SERVER['REQUEST_URI']`.
- **OWASP category:** A03 Injection (reflected XSS)
- **Problem:** Raw request data is placed into template variables and links without encoding. If templates print `CONTROLLER_THIS` or the `_link()` output without escaping, an attacker can craft a URL that injects HTML or script.
- **Severity:** Medium (depends on template escaping, which was not provided).
- **Fix:** Apply `htmlspecialchars(..., ENT_QUOTES)` (or `urlencode` for URL parts) when building these values.

### 6. Pre-existing: inverted underscore check in `populate_object()` (related file)
- **Location:** `Controller::populate_object()`: `if (!(strpos("_",$varname) === 0) ...`
- **OWASP category:** A04 Insecure Design
- **Problem:** The arguments to `strpos` are reversed. The intent is to skip setters for names starting with `_`, but the check tests the literal string `"_"` and is effectively always true. The `is_callable(array($obj, "set_".$varname))` check limits the impact, but the guard does not work as written.
- **Severity:** Low.
- **Fix:** Use `strpos($varname, "_") === 0` or `strncmp`.

### 7. Minor: loose comparison and reused optional-parameter ordering
- **Location:** `if($disable_exit == true)`; `retrieve_action($patient_id="", $document_id, ...)`.
- **OWASP category:** Insecure Design (hygiene).
- **Problem:** `==` with `true` accepts any non-empty string, so `disable_exit=anything` activates the bypass in finding 1. A default value placed before a required parameter is also deprecated in PHP 8.
- **Severity:** Low (the impact is covered by finding 1).
- **Fix:** Use strict checks, or remove the parameter entirely as recommended in finding 1.
