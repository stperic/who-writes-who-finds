Known vulnerability:
CVE-2026-33321 (server-side request forgery, OWASP A10), file interface/forms/eye_mag/report.php.
This change adds the eye exam report, which echoes stored, user-supplied values without
escaping into HTML and into CSS url() contexts (for example background: <?php echo $background; ?>
and free-text fields such as HPI, motility, visual field, Rx type and plan/order details). The
patient report page renders forms' report.php output server-side into a PDF with an HTML-to-PDF
renderer, which fetches URLs in the markup. Injected URLs are therefore fetched by the server:
out-of-band server-side request forgery. The root cause is the missing output escaping; the
same flaw also allows HTML injection in the browser view.

## Vulnerabilities Found

### 1. **SQL Injection (OWASP A03:2021 - Injection)**
**Location:** Line 69-70
```php
$query  = "SELECT * FROM form_eye_mag_prefs where PEZONE='PREFS' AND id=? ORDER BY ZONE_ORDER,ordering";
$result = sqlStatement($query,array($_SESSION['authUserID']));
```
**Issue:** While the parameterized query uses `?` placeholder (good), the use of `$_SESSION['authUserID']` directly in the array assumes it's already validated. However, if session data can be manipulated, this could be vulnerable.

**Location:** Line 2034
```php
$sql = "SELECT * from documents where documents.url like '%".$filename."'";
$doc = sqlQuery($sql);
```
**Severity:** **CRITICAL**
**Problem:** Direct string concatenation in SQL query without parameterization. The `$filename` variable is constructed from user-influenced data (`$pid`, `$encounter`, `$zone`) with no escaping.

**Location:** Line 1900
```php
$query = "select * from form_".$form_folder."_impplan where form_id=? and pid=? order by IMPPLAN_order ASC";
$result =  sqlStatement($query,array($form_id,$pid));
```
**Severity:** **HIGH**
**Problem:** Table name is concatenated directly (`"form_".$form_folder."_impplan"`). While `$form_id` and `$pid` use parameters, the table name itself is injectable if `$form_folder` is user-controlled.

### 2. **Broken Access Control (OWASP A01:2021)**
**Location:** Line 60-65
```php
if ($_REQUEST['CHOICE']) $choice = $_REQUEST['choice'];
if ($_REQUEST['ptid']) $pid = $_REQUEST['ptid'];
if ($_REQUEST['encid']) $encounter=$_REQUEST['encid'];
if ($_REQUEST['formid']) $form_id = $_REQUEST['formid'];
if ($_REQUEST['formname']) $form_name=$_REQUEST['formname'];
```
**Severity:** **CRITICAL**
**Problem:** 
- User input from `$_REQUEST` is accepted without validation or authorization checks
- No verification that the current user has access to the patient (`$pid`), encounter, or form
- An attacker can request any patient's data by modifying these parameters
- Missing ACL checks before querying and displaying patient information

## Key Recommendations

1. **Implement proper authorization checks** before retrieving patient data:
   ```php
   if (!acl_check('patients', 'med', $_SESSION['authUserID'], $pid)) {
       die('Access Denied');
   }
   ```

2. **Use prepared statements consistently** with parameter binding for all SQL queries

3. **Escape all output** with appropriate functions:
   - `text()` for plain text
   - `attr()` for HTML attributes
   - `js_escape()` for JavaScript contexts

4. **Validate and sanitize user input**:
   ```php
   $pid = isset($_REQUEST['ptid']) ? intval($_REQUEST['ptid']) : null;
   if (!$pid) die('Invalid patient ID');
   ```

5. **Remove `@extract()`** and explicitly reference variables

6. **Add comprehensive audit logging** for all patient data access

7. **Use strict comparison operators** (`===` instead of `==`)

8. **Validate file paths** before inclusion to prevent directory traversal
