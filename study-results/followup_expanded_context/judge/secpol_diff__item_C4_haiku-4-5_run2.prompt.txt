Known vulnerability:
CVE-2026-33321 (server-side request forgery, OWASP A10), file interface/forms/eye_mag/report.php.
This change adds the eye exam report, which echoes stored, user-supplied values without
escaping into HTML and into CSS url() contexts (for example background: <?php echo $background; ?>
and free-text fields such as HPI, motility, visual field, Rx type and plan/order details). The
patient report page renders forms' report.php output server-side into a PDF with an HTML-to-PDF
renderer, which fetches URLs in the markup. Injected URLs are therefore fetched by the server:
out-of-band server-side request forgery. The root cause is the missing output escaping; the
same flaw also allows HTML injection in the browser view.

# Security Review Report

## Summary
This code contains several **critical security vulnerabilities**, primarily in SQL injection and improper output encoding categories. Multiple issues across OWASP Top 10 categories were identified.

---

## Critical Issues

### 1. **SQL Injection - CRITICAL**
**Location:** Line 1892 in `display_draw_image()` function
```php
$sql = "SELECT * from documents where documents.url like '%".$filename."'";
```
**OWASP Category:** Injection (A03:2021)
**Problem:** User-controlled `$filename` is directly concatenated into SQL query without parameterization. The `$filename` is derived from database values but constructed from potentially user-influenced data (`pid`, `encounter`).
**Severity:** CRITICAL

**Location:** Line 72-73
```php
$query  = "SELECT * FROM form_eye_mag_prefs where PEZONE='PREFS' AND id=? ORDER BY ZONE_ORDER,ordering";
$result = sqlStatement($query,array($_SESSION['authUserID']));
```
**OWASP Category:** Injection (A03:2021)
**Problem:** While this query uses parameterization properly, the subsequent variable extraction with `$$LOCATION` is dangerous (see issue #6 below).
**Severity:** HIGH

---

### 2. **Broken Access Control - HIGH**
**Location:** Lines 62-66
```php
if ($_REQUEST['ptid']) $pid = $_REQUEST['ptid'];
if ($_REQUEST['encid']) $encounter=$_REQUEST['encid'];
if ($_REQUEST['formid']) $form_id = $_REQUEST['formid'];
if ($_REQUEST['formname']) $form_name=$_REQUEST['formname'];
```
**OWASP Category:** Broken Access Control (A01:2021)
**Problem:** User input from `$_REQUEST` is used to set `$pid` and `$encounter` without validation or access control checks. No verification that the current user has permission to access this patient's data.
**Severity:** CRITICAL

---

### 3. **Improper Output Encoding - HIGH**
**Location:** Multiple locations where `text()` is NOT used:
- Line 318: `echo $HPI1;` (should use `text()`)
- Line 654: `echo $PLAN2;` (should use `text()`)
- Line 2004: `echo  $item['plan'];` (should use `text()`)
- Many other instances throughout the file

**OWASP Category:** Injection - XSS (A03:2021)
**Problem:** Database output is echoed without proper escaping. User-supplied data stored in database could contain HTML/JavaScript that executes in the browser.
**Severity:** HIGH

---

### 4. **SQL Injection via Dynamic Variable Extraction - HIGH**
**Location:** Lines 72-76
```php
while ($prefs= sqlFetchArray($result))   {    
  $LOCATION = $prefs['LOCATION'];
  $$LOCATION = text($prefs['GOVALUE']);
}
```
**OWASP Category:** Injection (A03:2021) & Insecure Design (A04:2021)
**Problem:** Using `$$LOCATION` creates dynamic variable names based on database content. Combined with later use in queries or output without validation, this is extremely dangerous.
**Severity:** HIGH

## Recommendations

1. **Immediate:** Add access control validation after line 66:
```php
// Verify user has access to this patient
if (!acl_check('patients', 'med', false, array('write', 'addonly'))) {
  die("Unauthorized access");
}
```

2. **Immediate:** Use parameterized queries for all SQL (line 1892, 1945):
```php
$sql = "SELECT * from documents where documents.url LIKE ?";
$doc = sqlQuery($sql, array('%' . $filename . '%'));
```

3. **Urgent:** Add output encoding for all echoed variables:
```php
echo text($HPI1);  // Instead of echo $HPI1;
```

4. **Urgent:** Validate integer inputs:
```php
$pid = intval($_REQUEST['ptid'] ?? 0);
$encounter = intval($_REQUEST['encid'] ?? 0);
```

5. **Important:** Remove dynamic variable variables (`$$LOCATION`), use array instead.

6. **Important:** Use `htmlspecialchars($var, ENT_QUOTES, 'UTF-8')` consistently.
